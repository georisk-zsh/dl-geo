# data.csv 填表说明（算法④ XGBoost+SHAP 真实数据）

一张单点、逐日的宽表 CSV：**一行一天，一列一特征**。除下列原始列外，24 个派生特征（滞后、滚动统计、有效降雨等）由 Notebook 自动生成，无需手工计算。

## 列说明

| 列名 | 必填 | 含义 | 来源 |
|---|---|---|---|
| `date` | ✅ | 日期，`YYYY-MM-DD`，逐日、按时间排序、等间隔 | — |
| `disp_mm` | ✅ | **预测目标**：该测点累积位移（mm）。给累积值，不要给已差分的速率；InSAR+GNSS 融合场景下即 L2 融合 Kalman 输出 | L2 融合层 / 监测 |
| `rainfall_mm` | 建议 | 日降雨量（mm），最近雨量站 | 雨量站 |
| `reservoir_m` | 建议 | 库水位（m），坡脚受库水浸泡时是关键因子；无则留空 | 水文站 |
| `temp_c` | 可选 | 日均温（℃），冻融/热胀周期用 | 气象站 |
| `insar_vel` | 可选 | 该点周边（如 100 m）PS 点平均速率 | InSAR 处理链 |
| `coh_chg` | 可选 | 相干性及其变化率 | InSAR 处理链 |
| `dist_edge` | 可选 | 距坡缘距离等几何量（m） | 地形/几何 |

## 硬性要求

1. **时间跨度**：建议 ≥ 2 年（demo 用 6 年）。太短则调参/消融/SHAP 归因结论不稳。
2. **单点**：一张表对应一个测点；多测点则每个测点一张表（或长表交由我透视）。
3. **无泄漏**：所有特征必须是"预测当天已知"的量，不得包含当天之后的任何统计量。
4. **单位**：写清位移方向（LOS / 水平 / 垂直）与单位（mm 或 m），影响解读不影响代码。
5. **缺测**：某天缺值直接留空即可，后续统一做重采样/插值处理。

## 最省事起步

先填 `date, disp_mm, rainfall_mm, reservoir_m, temp_c` 五列即可全流程跑通（demo 同款结构）；之后再加 InSAR 特征族做对比。

放好数据后：改 Notebook §2.2 一格的 `DATA_PATH = "data.csv"`，先检查时间间隔与缺失情况，再跑基线 → 调参 → SHAP 归因。
