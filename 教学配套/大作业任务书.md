# 大作业任务书：边坡监测位移预测与归因（综合实战）

> 占总评 **50%**（报告 30% + 代码 10% + 答辩 10%）。1 人 1 题；鼓励 2 人组队做"对照实验组"（各写各的报告，数据/结论可互为对照）。
>
> **一句话目标**：拿到一份真实形状的监测数据，独立完成"预测 + 区间 + 归因"的完整闭环，并交付一份**经得起复核**的工程报告。

---

## 一、题目与数据

### 1.1 选题方向（三选一，题目自拟）

| 方向 | 任务 | 建议数据 |
|---|---|---|
| **A. 单点位移预测与归因** | 预测某监测点未来 1~7 天位移速率 + 不确定性区间 + 驱动因子归因 | 本仓库 [XGBoost+SHAP/data.csv](../XGBoost+SHAP/data.csv)、[LSTM/demo_geodata.csv](../LSTM/) 或自带 |
| **B. 多点监测网时空预测** | 对 ≥5 个测点做时空预测 + 逐节点误差空间分析 | [GCN/demo_gcn_geodata.csv](../GCN/) 或自带 |
| **C. 论文方法迁移复现** | 选一篇论文方法，在自带/公开数据上复现并做 ≥1 项改进 | work001 流程（[README](../work001/README.md)）为示范 |

### 1.2 自带数据要求

- **真实数据优先**（课题组监测数据、公开数据集均可），注明来源与授权；
- 真实数据**至少 1 年日频**（或 ≥300 个时间步）；不够可以用"真实 + 合成扩展"，但须声明合成方式；
- 无合适真实数据可用仓库演示数据，但**报告评分上限 27/30**（见评分表注）。

### 1.3 数据形状警告（先读再开工）

演示数据是"日频、单点/多点、含降雨+库水位+温度驱动"的设定。自带数据若形状差异大（如小时频、只有位移无驱动因子），在报告 §1 中说明你做了哪些适配——**适配得当是加分项，不是扣分项**。

## 二、必做任务（方法链七步，对应 README「1 条完整方法链」）

| 步 | 任务 | 工程规范（评分锚点） |
|---|---|---|
| ① **数据流水线** | 防泄漏划分与预处理 | 按**目标时刻**切分训练/验证/测试（测试段 = 时间最后 20%）；一切统计量（标准化、特征筛选、滞后选择）**只在训练段 fit**；窗口构造因果（历史窗口 → 未来目标）。做法详见[数据准备篇](../数据准备篇/) |
| ② **两级评估口径** | 速率目标 + 累积重构 | 速率口径：直接评估预测目标；累积口径：速率积分重构累积位移再评估。**两口径都要报**，并在报告中解释分歧（参照案例 Notebook 的评估章节） |
| ③ **基线** | ≥2 个 | 必含 persistence（明日=今日）；再任选线性回归 / ARIMA-Kalman / 从零 GBM |
| ④ **主模型** | ≥2 个 | 至少 1 个深度模型（LSTM / CNN-Transformer / GCN）+ 至少 1 个其他类（XGBoost / 第二个深度模型）。**至少 1 个模型的核心部分须从零实现（NumPy）并做数值梯度检查**（树模型可免，改做"增益公式暴力验证"，参照案例 4） |
| ⑤ **调参** | 随机搜索或贝叶斯 | 搜索空间、组数（≥20）、验证集设计、早停策略全部写入报告；给"搜索记录表" |
| ⑥ **物理融合改进** | ≥1 项 | 任选：渗流滞后核特征、单调性约束、图平滑正则、物理软约束损失。**必须有消融**（改进 vs 不改进的对照表） |
| ⑦ **不确定性区间** | 给预测区间 | MC Dropout / 分位数 / 合法性检查（conformal 思想）任一；报告区间覆盖率（名义 90% 的区间实际盖住多少） |

## 三、加分任务（任选，每项至多 +2，总分不超过 100）

- **归因/可解释**：SHAP / 注意力-滞后曲线 / 敏感性分析，回答"某次加速变形的主导驱动因子"（参照案例 3 §可解释性、案例 4 §SHAP）；
- **模型集成**：多模型加权集成并报告增益；
- **超前预警演示**：把区间预测接到"超越概率 → 预警等级"的简单风险矩阵；
- **与经典基线深度对照**：完整复现 [ARIMA-Kalman](../ARIMA-Kalman/) 并对比；
- **交互式结果页**：Streamlit / 静态 HTML 仪表盘均可。

## 四、交付物

| 交付物 | 格式 | 内容 |
|---|---|---|
| **工程报告** | PDF，正文 ≤12 页（不含附录） | 结构见 §4.1 |

| **答辩** | PPT ≤12 页，8 分钟讲 + 5 分钟问答 | 现场**随机抽问 1 个数字**要求你解释来源（防"报告不是自己写的"） |

### 4.1 报告结构（缺节扣分）

1. **问题定义与数据描述**：监测对象、数据来源、字段、时频、缺失与异常处理；
2. **数据流水线**：画出划分/fit 范围示意图，列"防泄漏动作清单"（至少 4 条，如：标准化仅训练段 fit / 按目标时刻切分 / 窗口因果 / 特征滞后对齐）；
3. **基线与主模型**：每个模型一段（原理 3 句话以内 + 结构图/参数表）；
4. **调参与消融**：搜索记录表 + 消融对照表（至少覆盖第 ⑥ 步的改进）；
5. **评估结果**：两级口径主表（模型 × 口径 × {RMSE, MAE, R², NSE}）+ 多步递归预测对比；**必须含失败案例分析**（哪段时间预测最差、为什么）；
6. **不确定性**：区间图 + 覆盖率表；
7. **归因与工程解读**（可选但强烈建议）；
8. **结论与局限**：≤500 字，明确回答"这个模型能不能用于该工程场景的什么决策"。

### 4.2 报告红线（触犯一条，本节 0 分且总分 ≤60）

- ❌ 测试段（或其统计量）以任何形式参与训练/调参/标准化——**数据泄漏**；
- ❌ 只报单一口径、或"选好看的口径报"；
- ❌ 调参结果表与代码实际运行对不上（以仓库代码复跑结果为准）；
- ❌ 无出处的数字（每个数字都要能指到某张表/某个 cell 的输出）。

## 八、常见问题

**Q：没有真实监测数据怎么办？**
用仓库演示数据，如实声明即可（报告上限 27/30）。另一个选择是方向 C：找一篇带公开数据的论文做迁移复现。

**Q：可以只用 PyTorch 全程，不做从零实现吗？**
不行——"从零实现 + 数值梯度检查"是本课的核心训练（第 ④ 步），但**只有 1 个模型需要**，其他模型随意用官方库。

**Q：GPU 是必需的吗？**
不是。数据规模在演示级别，CPU 几分钟内可跑完；GPU 只影响搜索组数的速度。

**Q：区间预测用 sklearn 的分位数回归行吗？**
行。但覆盖率要自己实现计算，并回答"实测覆盖率和名义 90% 差多少、为什么"。

**Q：报告里的"防泄漏动作清单"具体写什么？**
至少覆盖：划分按目标时刻、标准化/特征统计只在训练段 fit、滞后特征只用历史值、调参只碰验证段。参考各案例 Notebook 的 Checklist 章节。
