本章目标：在一台 Linux 服务器上装好 PostgreSQL 16，掌握启动/停止/查看状态，并打通"从你自己的电脑远程连接服务器上的 PostgreSQL"这条路。

> 🖥 **系统差异**
> - **macOS**：`brew install postgresql@16` 后用 `brew services start postgresql@16` 管理，配置文件在 `/opt/homebrew/var/postgresql@16/`；
> - **Windows**：去 [https://www.enterprisedb.com/downloads/postgres-postgresql-downloads](https://www.enterprisedb.com/downloads/postgres-postgresql-downloads) 下载 EDB 安装包，双击下一步即可（安装时可设置 `postgres` 用户密码），服务在"服务"管理器（`services.msc`）里名为 `postgresql-x64-16`。
> - 两者都**不需要** sudo -u postgres，直接 `psql -U postgres -h localhost` 输密码即可连。

## 2.1 两种安装方式怎么选（Ubuntu）

Ubuntu 自带的软件源里 PostgreSQL 版本通常较旧（如 22.04 自带 14），**推荐用 PostgreSQL 官方源（PGDG）安装 16**：

| 方式 | 版本 | 建议 |
|---|---|---|
| `apt install postgresql` | 系统源版本（可能偏旧） | 图省事可用 |
| **PGDG 官方源** | 最新（16/17） | **本教程推荐**，步骤见下 |

一键脚本：`scripts/00_install_ubuntu.sh`（可先 `cat` 阅读再执行）。手动步骤如下，理解每一步：

### 第 1 步：添加 PGDG 官方软件源

```bash
$ sudo apt update && sudo apt install -y curl ca-certificates
$ sudo install -d /usr/share/postgresql-common/pgdg
$ sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc --fail \
    https://www.postgresql.org/media/keys/ACCC4CF8.asc
$ . /etc/os-release
$ sudo sh -c "echo 'deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] \
    https://apt.postgresql.org/pub/repos/apt ${VERSION_CODENAME}-pgdg main' \
    > /etc/apt/sources.list.d/pgdg.list"
```

这几行做的事：下载官方签名密钥（`.asc`，apt 用它验证软件包没被篡改）→ 把官方源地址写入系统源列表 → 其中 `${VERSION_CODENAME}` 是你的 Ubuntu 代号（如 `noble`）。

### 第 2 步：安装

```bash
$ sudo apt update
$ sudo apt install -y postgresql-16
```

安装完的输出里能看到 `Success. You can now start the database server` 之类的字样。**Ubuntu 安装完会自动启动服务**，确认一下：

```bash
$ pg_lsclusters
```

```text
Ver Cluster Port Status Owner    Data directory                    Log file
16  main    5432 online postgres /var/lib/postgresql/16/main      /var/log/postgresql/postgresql-16-main.log
```

`Status = online` 说明 PostgreSQL 已经在 5432 端口提供服务了。

> **RHEL / Rocky / CentOS 简述**：先安装 PGDG 的 rpm 源包（官网有对应命令），再 `sudo dnf install -y postgresql16-server postgresql16-contrib`，初始化并启用：
> ```bash
> $ sudo /usr/pgsql-16/bin/postgresql-16-setup initdb
> $ sudo systemctl enable --now postgresql-16
> ```
> RHEL 系安装后服务**不会**自动启动，注意上面最后一句 `--now`。

## 2.2 记住这三个目录（Linux）

| 路径 | 内容 |
|---|---|
| `/var/lib/postgresql/16/main/` | **数据目录**：所有数据库数据真正存放的地方（删除=毁灭，别碰） |
| `/etc/postgresql/16/main/` | **配置目录**：`postgresql.conf`（主配置）、`pg_hba.conf`（谁可以连，[第 15 章](第15章_用户权限与安全.md)细讲） |
| `/var/log/postgresql/` | **日志目录**：出错先来这里看 `postgresql-16-main.log` |

## 2.3 第一次连接：sudo -u postgres psql

Ubuntu 安装时自动创建了一个名为 **`postgres` 的 Linux 系统用户**（数据库超级管理员在操作系统里的身份）。出于安全设计，这个账号**初始没有密码、禁止远程登录**，只能用下面方式"变身"后连接：

```bash
$ sudo -u postgres psql
```

- `sudo -u postgres` = "以 postgres 这个用户的身份执行后面的命令"；
- 成功后提示符变成 `postgres=#`（`#` 表示超级管理员）。

先跑三条"Hello World"级别的命令：

```sql
postgres=# SELECT version();          -- 查看 PostgreSQL 版本
postgres=# SELECT now();              -- 服务器当前时间（顺带验证时区）
postgres=# \l                         -- 列出所有数据库（\l 是小写 L）
```

`\l` 的输出应能看到 `postgres`、`template0`、`template1` 三个自带库（概念见 1.11 节）。

退出用：

```sql
postgres=# \q
```

> **macOS / Windows 用户**没有这一步：直接 `psql -U postgres -h localhost`，Windows 输安装时设置的密码即可；macOS 本机默认信任连接，回车就进。

## 2.4 启动、停止、重启、查看状态

PostgreSQL 在 Ubuntu/Debian 下由 **systemd + pg_ctlcluster** 双轨管理，两套命令效果等价：

```bash
$ sudo systemctl status postgresql@16-main     # 查看状态（按 q 退出查看）
$ sudo systemctl stop postgresql@16-main       # 停止
$ sudo systemctl start postgresql@16-main      # 启动
$ sudo systemctl restart postgresql@16-main    # 重启（改完部分配置需要）
$ sudo systemctl enable postgresql@16-main     # 开机自启（安装时通常已设好）
```

Debian 系特有的简写工具（更快，推荐）：

```bash
$ pg_lsclusters                                # 一览所有实例和状态
$ sudo pg_ctlcluster 16 main stop              # 停止 16/main 实例
$ sudo pg_ctlcluster 16 main start             # 启动
$ sudo pg_ctlcluster 16 main reload            # 重读配置（不中断服务，改 pg_hba.conf 后用）
```

> **服务器上一般别随手 restart**：restart 会断开所有连接。改配置优先 `reload`（[第 15 章](第15章_用户权限与安全.md)演示）。

> 🖥 **系统差异**
> - macOS：`brew services start|stop|restart postgresql@16`；
> - Windows：`net stop postgresql-x64-16` / `net start postgresql-x64-16`（管理员 PowerShell），或图形界面的服务管理器。

## 2.5 配置远程连接（重要：pgAdmin / 你的电脑连服务器）

默认情况下 PostgreSQL **只接受本机连接**。典型部署：数据库在 Linux 云服务器上，你在自己电脑用 pgAdmin 连过去，需要改两个文件 + 一个防火墙。

**① `postgresql.conf` —— 监听地址**（`/etc/postgresql/16/main/postgresql.conf`）：

```bash
$ sudo nano /etc/postgresql/16/main/postgresql.conf
```

找到 `listen_addresses` 一行（默认 `localhost`），改成：

```text
listen_addresses = '*'
```

保存退出（nano 中 `Ctrl+O` 回车保存，`Ctrl+X` 退出）。

**② `pg_hba.conf` —— 允许哪些 IP 的哪些用户连**（同目录下）：

在文件末尾追加一行（先只允许你自己的 IP，不要对全网开放）：

```text
host  beginner_pg  student_pg  203.0.113.10/32  scram-sha-256
```

格式：`host(允许TCP) 库名 用户名 来源IP/掩码 认证方式(密码加密)`。假设你的公网 IP 是 `203.0.113.10`，请替换成自己的。

**③ 防火墙放行 5432 端口**：

```bash
$ sudo ufw allow from 203.0.113.10 to any port 5432 proto tcp
$ sudo ufw status        # 确认规则生效
```

云服务器（阿里云/腾讯云/AWS）还需在**控制台的安全组**里放行 5432。

**④ 重载配置并测试**：

```bash
$ sudo pg_ctlcluster 16 main reload
```

在你的电脑上（需已装 psql 或 pgAdmin）：

```bash
$ psql -h 服务器IP -p 5432 -U student_pg -d beginner_pg
```

> **安全提醒**
> - 永远不要把 `0.0.0.0/0`（全网）加进 pg_hba.conf 并用弱密码——勒索脚本几分钟就能扫到你；
> - 认证方式用 `scram-sha-256`（PG 默认），别用 `trust`；
> - `student_pg` 此时还没创建、也还没密码——[第 4 章](第04章_数据库用户与模式.md)创建后这条规则才能真正连通。先把流程记住即可。

## 2.6 客户端工具：dbx + Termius/Tabby 远程连接与部署

2.5 节讲的方案是"把 5432 端口对特定 IP 开放"。本节介绍**另一条更安全的常用路线：SSH 隧道**，以及配套的两个工具——数据库客户端 **dbx** 和终端/SSH 客户端 **Termius（或 Tabby）**。这套组合是"数据库装在 Linux 服务器上、人在本地电脑操作"这种最常见的部署形态下，日常最好用的搭配。

### 2.6.0 先分清两个容易混的名字

| 名字 | 是什么 | 官网 |
|---|---|---|
| **Termius** | 跨平台 SSH / SFTP 客户端，专门做远程服务器连接管理（Windows/macOS/Linux/手机都有） | termius.com |
| **Tabby** | 开源终端模拟器，**原名 Terminus**（2020 年改名）。带 SSH 客户端与端口转发功能 | tabby.sh |

> 本节要用的核心功能是"**SSH 会话 + 本地端口转发**"，这两个工具都有，操作逻辑也基本一致。下文统称"终端工具"，凡菜单名称有差异的地方用表格并列说明。**先确认自己装的是哪一个**（看软件标题栏或"关于"页面），别把 Tabby 的教程拿去套 Termius。

### 2.6.1 为什么用 SSH 隧道：两种方案对比

先把两条路摆在一起——它们解决同一个问题（"本地电脑连服务器上的数据库"），但安全性和代价不同：

```text
【方案 A：直连（2.5 节）】

  本地 dbx ────── TCP 5432 ──────→ 服务器 5432（PostgreSQL）

  服务器要求：listen_addresses = '*'
              pg_hba.conf 里加你的公网 IP
              防火墙 / 云安全组放行 5432


【方案 B：SSH 隧道（本节）】

  本地 dbx ── TCP 15432 ──→ 本机 15432（SSH 客户端在监听）
                                 │
                                 └── SSH 加密（22 端口）──→ 服务器 127.0.0.1:5432（PostgreSQL）

  服务器要求：什么都不用改（listen_addresses 保持默认的 localhost）
              22 端口本来就开着，防火墙一行不动
```

| 对比项 | 方案 A 直连 | 方案 B SSH 隧道 |
|---|---|---|
| 5432 是否暴露公网 | **是**（能被全网扫描到） | **否**（公网看不到 5432） |
| 认证依据 | 数据库密码 | SSH 密钥/密码（数据库密码仍在隧道内传输） |
| 换网络/换 IP | 要改 pg_hba.conf + 防火墙 | 不用改任何服务器配置 |
| 服务器配置改动 | 两处 + 防火墙 | 零改动 |
| 代价 | 攻击面大，风险高 | 多一层转发，速度略慢 |

> **结论**：个人学习、小团队、云服务器场景，**优先用 SSH 隧道**。2.5 节的直连方式留给"内网服务器"或"需要固定 IP 的应用服务器连数据库"这类场景。
>
> 记住一句话：**SSH 隧道让数据库端口从公网上彻底消失**——你连的是自己电脑上的一个端口，数据由 SSH 加密送到服务器的 5432。

### 2.6.2 安装 dbx 与终端工具

**dbx**（数据库 GUI，约 20MB，开源，能管 90+ 种数据库）：

| 平台 | 安装命令 |
|---|---|
| macOS | `brew install --cask dbx` |
| Windows | `winget install t8y2.dbx`（或 Scoop 安装） |
| Linux | Flatpak 安装 `com.dbxio.dbx` |
| 全平台备选 | 从 GitHub Releases 直接下载安装包（github.com/t8y2/dbx） |
| 服务器自托管 | `docker run -p 4224:4224 t8y2/dbx:latest` |

**Termius / Tabby**：

- Termius：官网 termius.com 下载，注册账号后免费版即可用（SSH、SFTP、端口转发都包含）；手机端也有，临时看一眼服务器很方便；
- Tabby：官网 tabby.sh 下载；macOS 可 `brew install --cask tabby`。

### 2.6.3 第一步：在终端工具里保存 SSH 会话

打开终端工具，新建一个 SSH 会话，填写：

| 字段 | 填什么 |
|---|---|
| Host / 主机 | 服务器的**公网 IP**（或域名） |
| Port / 端口 | `22` |
| Username / 用户名 | **你的 Linux 系统账号**（如 `ubuntu`、`root`） |
| 认证方式 | 密码，或（**推荐**）私钥 |

> ⚠️ **新手第一大混淆点**：这里的用户名是 **Linux 系统账号**，不是数据库用户 `student_pg`！这是[第 1 章](第01章_数据库基础概念.md)讲的"两层身份"在实操中的体现：
> - **Linux 账号**（如 `ubuntu`）→ 决定你能否登录这台服务器、能碰系统里哪些文件；
> - **数据库账号**（如 `student_pg`）→ 决定你登录服务器之后，能否连数据库、能查哪些表。
>
> 两套体系完全独立。你能 SSH 上服务器 ≠ 你能连数据库；反之亦然。

**用密钥登录（比密码安全得多）**，本机终端执行：

```bash
$ ssh-keygen -t ed25519 -C "my-laptop"     # 一路回车，生成密钥对
$ ssh-copy-id ubuntu@服务器IP              # 把公钥装到服务器上
```

之后在终端工具的会话里选择刚生成的私钥文件（`~/.ssh/id_ed25519`）即可免密登录。密钥认证的好处：不怕被暴力破解，也不用把密码存在客户端里。

会话配好后保存为 profile（起个名字如 `我的学习服务器`），以后**双击即连**——这是终端工具相比裸敲 `ssh` 命令最大的价值。

### 2.6.4 第二步：配置本地端口转发（隧道）

在刚保存的会话配置里，找到"**端口转发 / Port Forwarding / Tunnels**"标签页，添加一条**本地转发（Local）**规则：

| 配置项 | 填写 | 说明 |
|---|---|---|
| 类型 Type | `Local` | 本地转发：本机端口 → 服务器端口 |
| Local address | `127.0.0.1` | 只监听本机，别人连不到你的隧道 |
| **Local port** | `15432` | 本机端口，**特意错开 5432**，避免和本机自己的 PostgreSQL 撞车 |
| Remote address | `127.0.0.1` | 从服务器自己的视角看数据库在哪 |
| **Remote port** | `5432` | 服务器上 PostgreSQL 的真实端口 |

> 几个工具里这个标签页的位置：
> - **Termius**：编辑会话 → `Port Forwarding` → `+` 添加规则；
> - **Tabby**：设置 → `Port forwarding` → 添加；
> - 也有工具写在会话的 `Tunnels` 或 `SSH → Forwarding` 里。找不到就在设置里搜 "forward"。
>
> 不装图形工具也能建隧道——任何时候都记住这条万能命令：
> ```bash
> $ ssh -L 15432:127.0.0.1:5432 ubuntu@服务器IP
> #      └本地端口 └目标地址(服务器视角)
> ```
> `-L` 就是 Local forwarding。终端工具做的是同一件事，只是帮你把命令图形化了。

**验证隧道是否通了**（本地电脑终端）：

```bash
$ psql -h 127.0.0.1 -p 15432 -U student_pg -d beginner_pg
```

能进到 `beginner_pg=>` 提示符，说明隧道 + 数据库认证全部打通。（`student_pg` 在[第 4 章](第04章_数据库用户与模式.md)创建；在此之前这一步会报认证失败，属正常。）

### 2.6.5 第三步：在 dbx 里连接 PostgreSQL

dbx 有两条路，**路线 1 更省事**：

#### 路线 1：dbx 自带 SSH 隧道（推荐）

dbx 原生支持 SSH 隧道（密钥和密码都支持），不需要额外的终端工具：

| dbx 连接表单 | 填什么 |
|---|---|
| 类型 | PostgreSQL |
| **SSH 隧道 / Tunnel** 标签 | 服务器 IP、端口 `22`、Linux 用户名、私钥或密码 |
| Host | `127.0.0.1`（**服务器视角**的地址，因为隧道是 dbx 自己建的） |
| Port | `5432` |
| Database | `beginner_pg` |
| Username / Password | `student_pg` / `student_pg_2024` |

#### 路线 2：先用终端工具开隧道，dbx 直连本地端口

先按 2.6.4 建好隧道（保持 SSH 会话处于连接状态），然后 dbx 里：

| 字段 | 填什么 |
|---|---|
| Host | `127.0.0.1` |
| Port | `15432`（你的隧道本地端口） |
| Database | `beginner_pg` |
| Username | `student_pg` |
| Password | `student_pg_2024` |

**两条路线怎么选？**

- 只想连数据库 → 路线 1（少一个软件）；
- **一条隧道给多个工具复用** → 路线 2。隧道一旦建好，dbx、psql、pgAdmin **都能同时连** `127.0.0.1:15432`，不用各配一遍 SSH 信息。这也是把隧道放在终端工具里的最大好处。

连接成功后你应该能看到：

```text
左侧树：Servers → 我的学习服务器 → Databases → beginner_pg
                                              └── Schemas → school → Tables
                                                              ├── students
                                                              ├── courses
                                                              └── enrollments
```

**这棵树就是[第 1 章](第01章_数据库基础概念.md)"服务器 → 数据库 → 模式 → 表"四层结构的可视化**。在 dbx 里打开 SQL 编辑器试一条：

```sql
SELECT version();          -- 服务器版本
SELECT COUNT(*) FROM school.students;    -- 15，说明数据和权限都通了
```

> **安全提示**：dbx 会把连接密码存在本地。给 dbx 设置一个**主密码（Master Password）**，别让密码明文躺在磁盘上。密钥文件同理，权限设成 `600`（`chmod 600 ~/.ssh/id_ed25519`）。

### 2.6.6 第四步：日常部署与运维操作

终端工具不只是"连数据库"，它同时是你**在服务器上干活**的入口——部署、传文件、跑脚本都靠它：

**① 传文件（SFTP）**

Termius 和 Tabby 都有 SFTP / 文件面板：登录服务器后切换到文件视图，**拖拽**即可上传下载。日常最常用的场景：

- 把本地的 SQL 脚本传上去（如[第 14 章](第14章_备份与恢复.md)的备份脚本、[第 16 章](第16章_综合项目_学生选课管理系统.md)的项目初始化脚本）；
- 把服务器上的备份文件 `.dump` 拉回本地保存（**异地一份**，[第 14 章](第14章_备份与恢复.md)的备份铁律）。

**② 跑脚本**

在 SSH 会话里直接执行（这才是 SQL 文件的正确打开方式）：

```bash
$ psql -h 127.0.0.1 -U student_pg -d beginner_pg -f ~/scripts/02_school_schema.sql
$ pg_dump -h 127.0.0.1 -U student_pg -d beginner_pg -Fc -f ~/backup_$(date +%F).dump
```

**③ 把常用命令存成代码片段**

两个工具都支持 **Snippet / 片段**：把"连数据库""做备份""看服务状态"这类常用命令存起来，之后一键发送。示例片段：

```bash
# 片段名：进入练习库
psql -h 127.0.0.1 -U student_pg -d beginner_pg

# 片段名：看服务状态与日志
pg_lsclusters && tail -50 /var/log/postgresql/postgresql-16-main.log

# 片段名：每日备份
pg_dump -h 127.0.0.1 -U student_pg -d beginner_pg -Fc -f ~/pg_backups/beginner_$(date +%F).dump
```

**④ 多标签 / 分屏**

[第 12 章](第12章_事务.md)的事务并发实验需要**两个会话同时活着**，用终端工具开两个标签页（或 dbx 开两个 Query 标签）比来回切终端舒服得多。

### 2.6.7 隧道专属问题排查

出了错先判断"错在哪一层"——隧道多了一层，报错也多了几种：

| 症状 | 卡在哪一层 | 解决 |
|---|---|---|
| 本地连 `127.0.0.1:15432` 直接 `Connection refused` | **隧道层** | 隧道随 SSH 会话断开而失效：确认 SSH 会话是"已连接"状态；确认转发规则已启用 |
| `FATAL: no pg_hba.conf entry for host "127.0.0.1"` | 数据库认证层 | 走隧道时服务器看到的来源是**它自己的 127.0.0.1**。确认 pg_hba.conf 里有 `host all all 127.0.0.1/32 scram-sha-256`（默认通常已有，见 2.5②） |
| `FATAL: password authentication failed for user "student_pg"` | 数据库认证层 | 密码错了——注意这是**数据库密码**，不是你登录服务器的 Linux 密码 |
| `database "beginner_pg" does not exist` | 数据库层 | [第 4 章](第04章_数据库用户与模式.md)还没执行建库脚本，或库名拼错 |
| `listen_addresses` 明明没改却连不上 | 服务层 | 服务器上先自测：`sudo -u postgres psql -c "SELECT 1;"`。本地能连而隧道连不上，问题在隧道；本地也连不上，问题在服务 |
| 本地 `15432 already in use` | 本机端口占用 | 换个本地端口（如 `15433`），同步改 dbx 的连接端口 |
| 隧道通了但**特别慢** | 网络层 | 正常现象：多一层加密转发。批量导数据建议直接在服务器上 `psql -f`，别绕隧道 |

> 排查顺序口诀：**先 SSH 能登录 → 再服务器本地 psql 能连 → 最后才试隧道端口**。一层一层来，比乱改配置快十倍。

### 2.6.8 小结：什么时候用哪个方案

| 场景 | 推荐 |
|---|---|
| 数据库在云服务器，个人/小团队使用 | **SSH 隧道**（本节），5432 不对公网开放 |
| 服务器在同一个内网，或应用服务器需要固定连接 | 直连 + pg_hba 白名单（2.5 节） |
| 只想临时看一眼数据 | 隧道 + dbx 路线 1（最快） |
| 要同时用 dbx、psql、pgAdmin 三个工具 | 终端工具建**一条隧道**，三个工具复用（路线 2） |
| 生产环境 | **连数据库一律走隧道**；需要直连时来源 IP 精确到 `/32`，绝不放 `0.0.0.0/0` |

## 2.7 升级与卸载（了解即可）

- **卸载但保留数据**：`sudo apt remove postgresql-16`（数据目录仍在 `/var/lib/postgresql/16/main`）；
- **连数据一起删（危险！）**：`sudo apt purge postgresql-16 && sudo rm -rf /var/lib/postgresql/16`——执行前想三遍；
- **跨大版本升级**（14→16）用 `pg_upgradecluster`，本教程不展开，知道有这条路即可。

## 常见安装问题排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `psql: command not found` | 只装了服务端没装客户端 | `sudo apt install -y postgresql-client-16` |
| `Connection refused` | 服务没启动 / 监听地址没放开 | `pg_lsclusters` 查状态；查 `listen_addresses` |
| `password authentication failed` | 密码错，或 pg_hba.conf 规则不匹配 | 核对用户密码；`reload` 使 pg_hba.conf 生效 |
| `FATAL: no pg_hba.conf entry` | 来源 IP 不在 pg_hba.conf 允许列表 | 加规则 + reload（见 2.5②） |
| 端口被占 `5432 already in use` | 已有一个实例在跑 | `pg_lsclusters` 看看；或新实例改端口 |

## 本章小结

- Ubuntu 推荐用 **PGDG 官方源**装 `postgresql-16`，装完自动启动，`pg_lsclusters` 查状态；
- 三个关键目录：**数据**（`/var/lib/...`，别碰）、**配置**（`/etc/...`）、**日志**（`/var/log/...`）；
- 管理服务：`systemctl` 或 Debian 系的 `pg_ctlcluster`，改配置优先 `reload` 而不是 `restart`；
- 远程连接三件套：`listen_addresses` + `pg_hba.conf` + 防火墙/安全组，来源 IP 越小越好；
- **更安全的替代方案是 SSH 隧道**（2.6 节）：服务器配置零改动，5432 不对公网暴露；常用组合是 **Termius/Tabby 建隧道 + dbx 连数据库**；
- 客户端工具的三层身份要分清：**Linux 账号**（能否登录服务器）、**SSH 密钥**（登录凭证）、**数据库账号**（`student_pg`，能否连库）；
- 隧道排错按顺序来：SSH 能登录 → 服务器本地 psql 能连 → 最后才试隧道端口；
- 首次连接用 `sudo -u postgres psql`，这是 Linux 上进入管理员会话的标准姿势。
