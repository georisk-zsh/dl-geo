## 15.1 权限模型总览

PostgreSQL 的权限体系分两层，**顺序不能乱**：

```text
第一层：能不能连？ ── pg_hba.conf + 角色的 LOGIN 属性 + 数据库的 CONNECT 权限
第二层：进来能干什么？ ── 对 schema 的 USAGE + 对表/函数等的 SELECT/INSERT/UPDATE/...
```

**连接权**（第一层）由三道闸门共同决定：

1. **pg_hba.conf**（服务器配置文件）：来源 IP + 目标库 + 用户 + 认证方式，逐条匹配（见 2.5 节；用 SSH 隧道则只需放行 `127.0.0.1`，见 2.6 节）；
2. 角色必须带 `LOGIN` 属性；
3. 角色**在目标库**有 `CONNECT` 权限（默认 public 角色人人有——除非显式回收）。

**对象权**（第二层）核心概念：

> **GRANT（授予）**把权限交给角色；**REVOKE（回收）**收回来；**PUBLIC** 是一个特殊的"全体角色"占位符。

## 15.2 权限矩阵：一张表有哪些权限

对**表**：`SELECT`（读）/ `INSERT` / `UPDATE` / `DELETE` / `TRUNCATE` / `REFERENCES`（建外键引用它）/ `TRIGGER` / `ALL`（全部）。

对**模式**：`USAGE`（能"路过"这个模式访问里面的对象）/ `CREATE`（能在模式里建对象）。

对**数据库**：`CONNECT` / `CREATE`（建 schema）/ `TEMPORARY`。

**记住这个两级事实**：访问 `school.students` 需要（1）模式 `school` 的 `USAGE` **加上**（2）表 `students` 的 `SELECT`，缺一个都会 `permission denied`。

## 15.3 实战：给"教学助理"开一个只读账号

需求：新同学 `ta_reader` 只能读 `school` 模式的所有表，不能改。以管理员执行：

```sql
-- ① 创建可登录角色
CREATE ROLE ta_reader LOGIN PASSWORD 'ta_reader_2024';

-- ② 允许进入 beginner_pg 库
GRANT CONNECT ON DATABASE beginner_pg TO ta_reader;

-- ③ 允许使用 school 模式（没有这句，就算授权了表也访问不到！）
GRANT USAGE ON SCHEMA school TO ta_reader;

-- ④ 授权模式内全部现存表的 SELECT
GRANT SELECT ON ALL TABLES IN SCHEMA school TO ta_reader;
```

验证（新开一个终端用 ta_reader 连接）：

```bash
$ psql -h localhost -U ta_reader -d beginner_pg
```

```sql
beginner_pg=> SELECT COUNT(*) FROM school.students;      -- ✓ 读没问题
beginner_pg=> UPDATE school.students SET city='X' WHERE student_id=1;
ERROR: permission denied for table students               -- ✓ 改被拒绝
beginner_pg=> CREATE TABLE school.hack (id int);
ERROR: permission denied for schema school                -- ✓ 建表被拒绝
```

**第五步（新手 100% 遗漏）：默认权限**——`ALL TABLES IN SCHEMA` 只管**已存在**的表，student_pg 明天新建的表 ta_reader 还是看不到。补一句：

```sql
ALTER DEFAULT PRIVILEGES FOR ROLE student_pg IN SCHEMA school
    GRANT SELECT ON TABLES TO ta_reader;
-- 今后 student_pg 在 school 里建的每一张表，自动带 ta_reader 的读权限
```

## 15.4 回收与修改

```sql
REVOKE SELECT ON ALL TABLES IN SCHEMA school FROM ta_reader;    -- 收回
REVOKE CONNECT ON DATABASE beginner_pg FROM PUBLIC;             -- 全体角色禁止连此库（收紧）
ALTER ROLE ta_reader PASSWORD '新密码';                          -- 改密码
ALTER ROLE ta_reader RENAME TO ta_viewer;                       -- 改名
DROP ROLE ta_reader;    -- 删除（该角色必须先没有任何权限/对象，见 4.8）
```

**角色当"组"用**（团队管理的正确姿势）：

```sql
CREATE ROLE readonly_group NOLOGIN;              -- 组：不能登录，只是权限容器
GRANT USAGE ON SCHEMA school TO readonly_group;
GRANT SELECT ON ALL TABLES IN SCHEMA school TO readonly_group;
ALTER DEFAULT PRIVILEGES FOR ROLE student_pg IN SCHEMA school
    GRANT SELECT ON TABLES TO readonly_group;

CREATE ROLE alice LOGIN PASSWORD '...';          -- 新成员 = 建号 + 入组，权限管理一处生效
CREATE ROLE bob   LOGIN PASSWORD '...';
GRANT readonly_group TO alice, bob;              -- alice/bob 继承组的全部权限
```

## 15.5 查看权限：三种途径

```sql
-- ① psql 快捷方式
\du                              -- 角色与成员关系
\dp school.*                     -- 模式内对象的权限表
\l+                              -- 各库的 CONNECT 权限

-- ② 信息视图（写程序/脚本时用）
SELECT grantee, table_name, privilege_type
FROM information_schema.role_table_grants
WHERE table_schema = 'school' AND table_name = 'students'
ORDER BY grantee;

-- ③ 看某个角色"实际"能不能做某事
SELECT has_table_privilege('ta_reader', 'school.students', 'SELECT');   -- true
```

`\dp` 输出速读：`=r/owner` 表示 PUBLIC 只读，`student_pg=arwdDxt/student_pg` 中每个字母是一种权限（a=insert, r=select, w=update, d=delete …）。

## 15.6 pg_hba.conf 与认证方式

`/etc/postgresql/16/main/pg_hba.conf` 每行一条规则，**从上到下第一条匹配即生效**：

```text
# TYPE  DATABASE      USER         ADDRESS          METHOD
local   all           postgres                      peer      ← sudo -u postgres 的原理
host    beginner_pg   student_pg   127.0.0.1/32     scram-sha-256  ← SSH 隧道走的就是这条
host    beginner_pg   student_pg   203.0.113.10/32  scram-sha-256  ← 2.5 节的直连规则（按需）
host    all           all          0.0.0.0/0        reject         ← 兜底拒绝
```

> 💡 **注意第 2 行和第 3 行的取舍**：如果按第 2.6 节用 **SSH 隧道**，客户端数据总是从服务器自己的 `127.0.0.1` 进来——所以**只需要第 2 行，第 3 行（公网 IP 直连）完全可以不写**。少一条规则，就少一个被扫描的入口。这正是隧道方案在[第 15 章](第15章_用户权限与安全.md)"安全清单"里的价值。

认证方式（METHOD）选型：

| 方式 | 安全性 | 说明 |
|---|---|---|
| `scram-sha-256` | ✅ 推荐 | 密码加盐哈希验证（PG 14+ 默认） |
| `md5` | 过时 | 旧式哈希，新系统别用 |
| `peer` | 仅本机 | 校验系统用户名=数据库用户名（只支持 local 连接） |
| `trust` | ☠️ | **免密**！任何能连上端口的人直接进——绝不允许出现在生产网 |
| `cert` | 最强 | 客户端证书认证，高安全场景 |

改完必须 `sudo pg_ctlcluster 16 main reload` 生效。排错口诀：`FATAL: no pg_hba.conf entry` = 来源不在任何一条允许规则里。

## 15.7 SQL 注入：所有数据库的头号敌人

原理一句话：**把用户输入拼进 SQL 字符串，输入里夹带的 SQL 就会被执行**。

```python
# ✗✗✗ 危险写法（拼字符串）——用户输入 "1; DROP TABLE school.students; --" 会怎样？
sql = f"SELECT * FROM school.students WHERE student_no = '{user_input}'"

# ✓✓✓ 正确写法（参数化查询）：占位符 %s 的值永远不会被当作 SQL 执行
cur.execute("SELECT * FROM school.students WHERE student_no = %s", (user_input,))
```

防御清单：

1. **永远参数化查询**（Python 用 psycopg 的 `%s` 占位符；psql 脚本用 `\set` 或 `-v` 变量，别拼字符串）；
2. **应用连库用最小权限账号**（只授权它需要的表和操作，绝不用 postgres 超管连应用）；
3. psql 脚本安全用变量：`psql -v target='S2023001' -f query.sql`，脚本里 `WHERE student_no = :'target'`。

## 15.8 安全清单（生产上线前逐条打勾）

- [ ] 超级管理员 `postgres` 只在本机 peer 认证使用，不设远程、不给应用；
- [ ] 每个应用/每人一个独立账号，权限最小化（只读就只给 SELECT）；
- [ ] 密码：长且随机；`scram-sha-256` 认证；不写进代码库（用环境变量/密码文件 `.pgpass`，权限 600）；
- [ ] pg_hba.conf：来源 IP 精确到 /32，末尾兜底 reject，无 trust；
- [ ] `REVOKE CONNECT ON DATABASE xxx FROM PUBLIC`（私库禁止陌生角色连接）；
- [ ] 备份自动化 + 异地存放 + 恢复演练（[第 14 章](第14章_备份与恢复.md)）；
- [ ] 系统层：5432 端口不对公网全开（防火墙/安全组），系统补丁更新；
- [ ] 敏感列（身份证、手机号）考虑 pgcrypto 加密存储或应用层加密。

## 本章小结

- 两层权限：先过连接关（pg_hba.conf + LOGIN + CONNECT），再过对象关（USAGE + 表权限）；
- GRANT/REVOKE 管授收，`ALTER DEFAULT PRIVILEGES` 管未来的表，**组角色 + 成员继承**是团队正解；
- `\dp`、`information_schema.role_table_grants`、`has_table_privilege()` 三种查看途径；
- pg_hba.conf 自上而下首条匹配，生产禁 trust、IP 精确、兜底 reject；
- SQL 注入靠参数化查询根治；应用账号最小权限是最后的保险丝。
