两条数据库界的铁律：

1. **没做过恢复演练的备份等于没备份**；
2. 剩下的都是细节。

本章在 Linux 终端操作（不是 psql 内），工具是 `pg_dump` / `pg_restore` / `psql`。

## 14.1 备份工具全景

| 工具 | 备什么 | 格式 | 典型场景 |
|---|---|---|---|
| `pg_dump` | **单个数据库** | SQL 文本 / 自定义 / 目录 | 日常备份、迁移（本教程主角） |
| `pg_dumpall` | **整个集群**（全部库 + 全局对象：角色、表空间） | SQL 文本 | 服务器整体搬迁 |
| `pg_basebackup` | 物理全量 + WAL | 二进制 | 建立从库、PITR（进阶） |

> **容易忽略的坑**：`pg_dump` 备份**不含角色和密码**（角色属于"集群级"对象）。新服务器恢复完库常常连不上——因为没恢复用户。整集群迁移要用 `pg_dumpall --globals-only` 补上角色。

## 14.2 实战一：SQL 文本格式（可读、通用）

```bash
$ pg_dump -h localhost -U student_pg -d beginner_pg -f backup.sql
# 生成一大段可读的 SQL：建表、约束、数据（INSERT/COPY）、索引……
$ head -30 backup.sql          # 看看里面是什么
$ grep -c "INSERT INTO\|COPY " backup.sql
```

**恢复到哪个库？** SQL 备份不含 `CREATE DATABASE`，恢复前目标库要存在（psql 的 `--set` 或 `-1` 单事务可选）：

```bash
$ psql -h localhost -U student_pg -d postgres -c "CREATE DATABASE restore_test OWNER student_pg;"
$ psql -h localhost -U student_pg -d restore_test -f backup.sql
# 验证
$ psql -h localhost -U student_pg -d restore_test -c "SELECT COUNT(*) FROM school.students;"
```

## 14.3 实战二：自定义格式（压缩、可选择性恢复，推荐）

```bash
$ pg_dump -h localhost -U student_pg -d beginner_pg -Fc -f backup.dump
#      -Fc = custom 自定义格式（自带压缩，体积约为文本的 1/3）
$ pg_restore --list backup.dump        # 查看备份内容清单（带编号）

$ psql -h localhost -U student_pg -d postgres -c "CREATE DATABASE restore_test2 OWNER student_pg;"
$ pg_restore -h localhost -U student_pg -d restore_test2 backup.dump
# 常用选项：
#   -j 4            4 个并行任务恢复（大库提速明显）
#   -t students     只恢复这一张表
#   -c              恢复前先 DROP 已有对象（危险，看清再按）
```

## 14.4 两种格式怎么选

| | SQL 文本（-f xxx.sql） | 自定义（-Fc -f xxx.dump） |
|---|---|---|
| 可读性 | ✅ cat 直接看 | ❌ 二进制 |
| 恢复工具 | 任何 psql | 只能 pg_restore |
| 压缩 | 可外挂 gzip | ✅ 内置 |
| 并行恢复 | ❌ | ✅ `-j N` |
| 选择性恢复 | ❌ | ✅ 只恢复某些表 |
| 跨大版本 | ✅ 最稳 | ✅ |

**个人/教学项目：SQL 文本**（可读可 diff，能进 git）；**生产：自定义格式**（压缩 + 并行 + 选择性）。

## 14.5 只备份/恢复单张表

```bash
$ pg_dump -h localhost -U student_pg -d beginner_pg -t school.students -f students.sql
$ pg_restore --data-only -t enrollments backup.dump    # 只灌数据不建结构
```

`-t` 可多次指定多张表；`--data-only` / `--schema-only` 分别只要数据 / 只要结构（复制表结构的快捷方式）。

## 14.6 定时备份：cron + 日期文件名（Linux 生产标配）

写个备份脚本 `/home/me/pg_backup.sh`（把用户/路径换成你的）：

```bash
#!/bin/bash
# 每日备份 beginner_pg，保留 14 天
set -euo pipefail

BACKUP_DIR="$HOME/pg_backups"
STAMP=$(date +%Y%m%d_%H%M)
mkdir -p "$BACKUP_DIR"

pg_dump -h localhost -U student_pg -d beginner_pg -Fc \
    -f "$BACKUP_DIR/beginner_pg_$STAMP.dump"

# 删除 14 天前的旧备份
find "$BACKUP_DIR" -name "beginner_pg_*.dump" -mtime +14 -delete

echo "[$STAMP] backup done: $BACKUP_DIR/beginner_pg_$STAMP.dump"
```

```bash
$ chmod +x ~/pg_backup.sh          # 给执行权限
$ ~/pg_backup.sh                   # 手动跑一次验证
```

加入 crontab（每天凌晨 2:30 执行）：

```bash
$ crontab -e
# 在打开的文件末尾添加：
30 2 * * * /home/me/pg_backup.sh >> /home/me/pg_backup.log 2>&1
```

> 备份三问（每季度自检）：**能不能恢复？恢复要多快？备份在另一台机器上吗？**——备份文件和数据库同盘/同机器，机器挂了就全没了。用 `rsync` 或对象存储异地一份。

> 💡 **顺手实现"异地一份"**：如果你平时用 Termius/Tabby 管服务器（第 2.6 节），直接在它的 SFTP 文件面板里把 `~/pg_backups/*.dump` **拖到本机**即可——服务器炸了，备份还在你笔记本上。

## 14.7 恢复演练：把整库推倒重来

在练习库上演练一次"删库跑路"（**别在真实生产库做**）：

```bash
$ psql -h localhost -U student_pg -d postgres -c "DROP DATABASE beginner_pg;"   # 事故！
$ psql -h localhost -U student_pg -d postgres -c "CREATE DATABASE beginner_pg OWNER student_pg;"
$ pg_restore -h localhost -U student_pg -d beginner_pg backup.dump
$ psql -h localhost -U student_pg -d beginner_pg -c "SELECT COUNT(*) FROM school.enrollments;"
# 数据回来了，这就是备份的意义
```

## 14.8 权限与远程备份注意

- **pg_dump 的版本要 ≥ 服务器版本**（用 16 的客户端备 14 的库可以，反过来报错 `server version mismatch`）；
- 备份账号需要对全库对象有读权限（[第 15 章](第15章_用户权限与安全.md) GRANT SELECT ON ALL TABLES）；
- 远程备份直接 `-h 服务器IP`（走 2.5 节的网络配置），备份文件落在**本地**——顺手就完成了"异地一份"；
- 大库备份时避免影响业务：低峰执行；备库上备份（进阶）。

## 本章小结

- `pg_dump` 单库（SQL 文本 / 自定义 `-Fc`），`pg_dumpall` 全集群含角色；
- SQL 文本可读通用，自定义格式压缩+并行+选择性恢复；
- 恢复前先建空库；`pg_restore --list` 看清单、`-t` 选表、`-j` 并行；
- 定时备份 = 脚本 + cron + 日期文件名 + 保留策略 + **异地存放**；
- 备份必须做恢复演练——今天你已演练过一次"删库恢复"。
