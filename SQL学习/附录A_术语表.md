每条术语的格式统一是：**中文名（英文原名/缩写）** + **一句话大白话解释** + **首次出现章节**（带链接，方便你跳回原文看完整上下文）。章节链接指向该术语**第一次被正经讲解**的地方，不一定是最先出现这几个字的段落。

## A.1 基础概念

本类按**由浅入深的逻辑顺序**排列：从"数据是什么"一路走到"为什么要分表"。

| 术语 | 大白话解释 | 首次出现章节 |
|---|---|---|
| 数据（Data） | 对客观事物的记录，文字、数字、日期、图片、真假判断都算。 | [第 1 章](第01章_数据库基础概念.md) |
| 数据库（Database） | 长期存放在计算机里、有组织、可共享的数据集合；类比"一个带标签的文件夹"。 | [第 1 章](第01章_数据库基础概念.md) |
| 数据库管理系统（DBMS, Database Management System） | 专门管理数据库的软件；数据库是书，DBMS 是图书馆的管理制度加管理员。 | [第 1 章](第01章_数据库基础概念.md) |
| 关系型数据库管理系统（RDBMS, Relational Database Management System） | 用"多张二维表 + 表之间的关联"来组织数据的 DBMS；PostgreSQL、MySQL、Oracle 都属这一类。 | [第 1 章](第01章_数据库基础概念.md) |
| 关系型数据库（Relational Database） | 由多张二维表组成、表之间靠"编号引用"关联的数据库；见"规范化"。 | [第 1 章](第01章_数据库基础概念.md) |
| 二维表 | 就是 Excel 里那种横竖交叉的网格；关系型数据库的基本存储形态。 | [第 1 章](第01章_数据库基础概念.md) |
| 数据冗余（Data Redundancy） | 同一条信息在库里被存了很多遍，浪费空间还容易前后不一致；分表就是为了消除它。 | [第 1 章](第01章_数据库基础概念.md) |
| 实体（Entity） | 业务里一类需要被管理的东西，比如"学生""课程"；设计表时**一类实体一张表**。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| 规范化（Normalization） | "拆成多张表、各自存各自的信息、用编号互相引用"的设计思想，目的是消除冗余、保证一致。 | [第 1 章](第01章_数据库基础概念.md) |
| 约束（Constraint） | 写入数据时自动执行的校验规则，比如"分数必须是 0~100"；规则在数据库层，比应用层校验可靠。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| PostgreSQL（简称 PG） | 一款开源免费、功能强大、对 SQL 标准支持最完整的关系型数据库管理系统，Logo 是一头大象。 | [第 1 章](第01章_数据库基础概念.md) |
| PGDG 官方源（PostgreSQL Global Development Group） | PostgreSQL 官方维护的软件源；Ubuntu 自带源版本偏旧，教程推荐用它装 16/17。 | [第 2 章](第02章_安装与服务管理.md) |
| 客户端/服务器架构（C/S, Client/Server） | 客户端（psql、pgAdmin、你写的程序）发 SQL，服务器执行并把结果传回来。 | [第 1 章](第01章_数据库基础概念.md) |
| 数据库服务器（Database Server） | 一台装了 PostgreSQL 软件、专门对外提供数据存取服务的计算机，通常是 Linux 服务器。 | [第 1 章](第01章_数据库基础概念.md) |
| 集群（Cluster） | PostgreSQL 的"一个实例 + 它管理的数据目录"整体；`pg_lsclusters` 列的每一个就是一个集群。 | [第 2 章](第02章_安装与服务管理.md) |
| 实例（Instance） | 运行在服务器上、监听端口、管理一个数据目录的那套 PostgreSQL 进程；`16/main` 就是一个实例名。 | [第 2 章](第02章_安装与服务管理.md) |
| 数据与信息的关系 | 数据是原料，经过组织和查询变成能用于决策的信息；本教程的出发点是"数据在变大、变多人的时候怎么管"。 | [第 0 章](第00章_学习准备.md) |

## A.2 对象与层级

本类按**层级从大到小**排列：服务器 → 数据库 → 模式 → 表 → 列/行，然后是建在这些层上的其他对象。

| 术语 | 大白话解释 | 首次出现章节 |
|---|---|---|
| 层级结构 | "服务器 → 数据库 → 模式 → 表"四层，本教程主线是 `服务器 → beginner_pg → school → 五张表`；这张图必须刻在脑子里。 | [第 1 章](第01章_数据库基础概念.md) |
| `postgres` 数据库 | 安装时自带的默认库，一般不用来存业务数据。 | [第 1 章](第01章_数据库基础概念.md) |
| `postgres` 用户 | 自带的超级管理员账号；在 Linux 上还对应一个同名的系统用户。 | [第 1 章](第01章_数据库基础概念.md) |
| `public` 模式 | 每个数据库自带的默认模式，不指定模式时表会建在这里；**PG 15 起它的 CREATE 权限从"所有人"收紧为"仅数据库所有者"**。 | [第 1 章](第01章_数据库基础概念.md) |
| `pg_database_owner` | PG 15 起 `public` 模式的所有者，"当前数据库所有者"的占位符——所以库主天然能在 public 里建表。 | [第 4 章](第04章_数据库用户与模式.md) |
| `template0` / `template1` | 建新库时用来"复制一份"的模板库，`\l` 里能看到，平时不动它们。 | [第 2 章](第02章_安装与服务管理.md) |
| 表（Table） | 数据的整体容器，一张二维网格；业务里一类实体一张表。 | [第 1 章](第01章_数据库基础概念.md) |
| 列（Column） | 表头的每一项，规定一类信息，且有固定数据类型（文本/日期/数字）。 | [第 1 章](第01章_数据库基础概念.md) |
| 字段（Field） | 列的另一种叫法；"students 表有 5 个字段"等于"有 5 列"。 | [第 1 章](第01章_数据库基础概念.md) |
| 行（Row） | 一条完整的信息，网格里横着的一整条。 | [第 1 章](第01章_数据库基础概念.md) |
| 记录（Record） | 行的另一种叫法，1 行 = 1 条记录。 | [第 1 章](第01章_数据库基础概念.md) |
| 关系（Relation）/ 元组（Tuple） | 关系型理论里"表"叫关系、"行"叫元组；平时不用这些词，面试可能会问。 | [第 1 章](第01章_数据库基础概念.md) |
| 模式（Schema） | 数据库内部的"文件夹"，把表按用途分组；`school`、`library` 互不干扰，同名表可以共存。 | [第 1 章](第01章_数据库基础概念.md) |
| 搜索路径（search_path） | 告诉 PostgreSQL"不写模式前缀时按什么顺序找表"；教程设成 `school, public`，所以能直接写 `students`。 | [第 4 章](第04章_数据库用户与模式.md) |
| 全限定表名 | 带前缀的完整写法 `库.模式.表`，如 `beginner_pg.school.students`；实际写 SQL 时通常省略库名。 | [第 1 章](第01章_数据库基础概念.md) |
| 别名（Alias） | 给列或表起的临时名字，用 `AS` 指定；多表查询里用 `s`、`e` 这种短别名消歧。 | [第 7 章](第07章_查询基础.md) |
| 视图（VIEW） | 把一条复杂查询存起来、当成"虚拟表"用的对象；**存查询不存数据**，每次查询实时计算。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 可更新视图 | 结构简单的视图，PG 支持直接对它 INSERT/UPDATE，改动会落到基表上。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 函数（Function） | 把一段业务逻辑封装成"按钮"、可以反复调用的对象；教程用 PL/pgSQL 写了 `fn_set_score`。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| PL/pgSQL | PostgreSQL 内置的过程化语言，能写变量（DECLARE）、分支（IF）、提前 RETURN；会写它，SQL 就从查询语言升级成开发语言。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 存储过程式用法 | 把"一个业务动作"（如选课）写成一整段带判断和事务的 SQL，而不是零散敲几条语句。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 触发器（TRIGGER） | 数据变更时自动执行的钩子，常用于自动留痕、写审计日志。（进阶，见[第 16 章](第16章_综合项目_学生选课管理系统.md)进阶路线） | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| INSTEAD OF 触发器 | 让复杂视图也能被写入的机制。（进阶，见[第 16 章](第16章_综合项目_学生选课管理系统.md)进阶路线） | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 分区表 | 把一张逻辑大表按月等规则拆成多个物理小表，日志类大表常用。（进阶，见[第 16 章](第16章_综合项目_学生选课管理系统.md)进阶路线） | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 扩展（Extension） | 给 PG 加装的能力包；教程提到过 `pg_trgm`（模糊搜索）、PostGIS（地理）、pgvector（AI 向量）、TimescaleDB（时序）。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| ER 图（Entity-Relationship Diagram） | 画实体和它们之间关系的图；教程画的是"四实体 + 一关系表"。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 一对多（1:n） | 一个院系有多名教师，这种"一方对多方"的关系；靠外键落在"多"的那张表上。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 多对多（n:n） | 学生和课程互相多对多；必须靠一张中间表（如 `enrollments`）落地。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| 基表（Base Table） | 真正存数据的物理表，和视图这种"虚拟表"相对。 | [第 16 章](第16章_综合项目_学生选课管理系统.md) |

## A.3 数据类型与约束

本类先按**类型族**（数值 → 文本 → 日期时间 → 布尔特殊）排，再按**约束六件套**的顺序排。

| 术语 | 大白话解释 | 首次出现章节 |
|---|---|---|
| 数据类型（Data Type） | 规定一列能存什么、能参与什么运算、能加什么约束；选类型的原则是"够用就好、语义准确"。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `integer`（int4） | 常用整数类型，范围约 ±21 亿，日常首选（年龄、数量、id）。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `bigint`（int8） | 大整数，范围约 ±9.2×10¹⁸，用于订单号、日志 id。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `smallint`（int2） | 小整数，省空间，少用。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `numeric(p, s)` / `decimal` | **精确**小数，p 是总位数、s 是小数位；钱、成绩、利率一律用它。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `real` / `double precision` | 近似小数，有浮点误差；`0.1 + 0.2` 算出 `0.30000000000000004`，**禁止存钱和成绩**。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `varchar(n)` | 变长文本，最多 n 个字符；**n 是字符数不是字节数**，中文一个字算一个。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `text` | 变长文本，无长度上限；PG 里它和 `varchar` 性能几乎无差别。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `char(n)` | 定长文本，不足自动补空格，基本只在固定编码场景用。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `date` | 只存日期，如 `2025-09-01`；生日、开学日期这类纯"日期"概念用它。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `time` | 只存时刻，如 `08:30:00`。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `timestamp` | 日期 + 时刻，不带时区。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `timestamptz` | 日期 + 时刻 + 时区；内部存 UTC、显示随会话时区，**记录"发生了什么"一律用它**。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `interval` | 时间长度类型，如 `INTERVAL '2 days'`；可以跟日期相加做算术。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `boolean` | 只有三个值：`true` / `false` / `NULL`。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `NULL` | "未知/不存在"，不是 0 也不是空字符串；系统讲解在[第 10 章](第10章_NULL与常用函数.md)的三值逻辑。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `uuid` | 全局唯一标识符，分布式系统常用。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `jsonb` | JSON 文档类型，能存结构灵活的数据（进阶，知道存在即可）。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| 主键（Primary Key） | 表里用来唯一标识每一行的一列或几列，像学生的学号；三条硬规矩：唯一、非空、稳定。 | [第 1 章](第01章_数据库基础概念.md) |
| 复合主键 | 由多列一起组成的主键；一张表只能有一个主键。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| 外键（Foreign Key） | 本表中指向另一张表主键的列，表示"我这行属于你那行"；能挡住脏数据，也能表达关联。 | [第 1 章](第01章_数据库基础概念.md) |
| 引用完整性（Referential Integrity） | 外键保证"引用的对方一定存在"这条规矩的总称。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `REFERENCES` | 建外键时的关键字写法：`列 integer REFERENCES 对方表(主键列)`。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `ON DELETE` 行为 | 对方表的行被删时本表怎么办：`NO ACTION`（默认，拒绝）、`RESTRICT`、`CASCADE`（跟着删）、`SET NULL`（置空）、`SET DEFAULT`。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `CASCADE` | 级联删除：删学生，他的选课记录一起删——因为选课记录离开学生就没有意义。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `SET NULL` | 删教师时课程保留但 `teacher_id` 变 NULL，表示"暂无授课教师"。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `UNIQUE` 唯一约束 | 该列的值不许重复；一张表可以有多个 UNIQUE 列，且**允许 NULL**（主键不行）。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| 复合唯一约束 | 多列组合起来不重复，例如 `(student_id, course_id)` 保证同一学生同一课程只能选一次。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `NOT NULL` 非空约束 | 这一列必须填写，不许留空。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `CHECK` 检查约束 | 自定义校验，任何返回 true 的布尔表达式都行；比如 `CHECK (score BETWEEN 0 AND 100)`。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `DEFAULT` 默认值 | 不填这一列时自动用的值；`CURRENT_DATE`、`now()` 这类"动态默认值"每次插入时求值。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `GENERATED ALWAYS AS IDENTITY` | 现代的自增主键写法，编号永远由数据库分配，手工插值会被拒绝。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `GENERATED BY DEFAULT` | 自增但允许手工指定值，迁移数据时用。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `SERIAL` | 老教程里的自增写法，效果类似 IDENTITY；**新项目请用 IDENTITY**（SQL 标准）。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `CREATE TABLE` | 建表语句，属 DDL；列定义、类型、约束都在里面写清。 | [第 5 章](第05章_建表_数据类型与约束.md) |
| `ALTER TABLE` | 改已有表的结构：加列、删列、改类型、加/删约束、改列名表名。 | [第 5 章](第05章_建表_数据类型与约束.md) |

## A.4 查询与运算

本类按**由易到难**排列：先 SELECT 骨架与筛选，再聚合分组，再 JOIN，最后子查询/CTE/窗口函数。

| 术语 | 大白话解释 | 首次出现章节 |
|---|---|---|
| `SELECT` | 查询语句的骨架，回答"取哪些列、从哪儿取、要哪些行"；**它不修改任何数据，放心大胆试**。 | [第 7 章](第07章_查询基础.md) |
| 投影（Projection） | SELECT 后面列出来的那部分，决定结果里出现哪些列。 | [第 7 章](第07章_查询基础.md) |
| `*` 通配符 | 表示"所有列"；只适合人眼看，写进程序或报表的查询要显式列名。 | [第 7 章](第07章_查询基础.md) |
| `FROM` | 指定数据来源，可以是一张表、一段 JOIN，也可以是一个子查询。 | [第 7 章](第07章_查询基础.md) |
| `AS` | 给列或表起别名：`city AS 城市`、`school.students AS s`。 | [第 7 章](第07章_查询基础.md) |
| `||` 拼接运算符 | 把字符串连起来：`name || '（' || city || '）'`。 | [第 7 章](第07章_查询基础.md) |
| `WHERE` | 行过滤器，只保留条件为 true 的行；**没有 WHERE 的 UPDATE/DELETE 是全表事故**。 | [第 7 章](第07章_查询基础.md) |
| 比较运算符 | `=`（一个等号，不是 `==`）、`<>` 或 `!=`、`>`、`<`、`>=`、`<=`。 | [第 7 章](第07章_查询基础.md) |
| `BETWEEN ... AND ...` | 区间判断，**闭区间**，含两端：`BETWEEN 80 AND 90` 就是 80 ≤ x ≤ 90。 | [第 7 章](第07章_查询基础.md) |
| `IN (值1, 值2, ...)` | 判断是否落在一串值里：`WHERE city IN ('北京', '上海')`。 | [第 7 章](第07章_查询基础.md) |

| `IS NULL` / `IS NOT NULL` | 判断空值的唯一正确写法；**不能用 `= NULL`**，那样永远查不到行。 | [第 7 章](第07章_查询基础.md) |
| 逻辑运算符（AND / OR / NOT） | 组合条件的三个运算；优先级 `NOT > AND > OR`，混用无脑加括号。 | [第 7 章](第07章_查询基础.md) |
| `ORDER BY` | 排序；默认 `ASC` 升序，`DESC` 降序；可以多列排序。**没有 ORDER BY 就没有顺序保证**。 | [第 7 章](第07章_查询基础.md) |

| `DISTINCT` | 去重，作用在**整个选出的列组合**上，不是单列。 | [第 7 章](第07章_查询基础.md) |
| 子句顺序 | 书写顺序固定为 `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`，不能乱。 | [第 7 章](第07章_查询基础.md) |
| 聚合函数（Aggregate Function） | 把一摞行压缩成一个数：`COUNT`、`SUM`、`AVG`、`MAX`、`MIN`。 | [第 8 章](第08章_聚合与分组.md) |
| `COUNT(*)` | 数行数，**全部行都数**（包括含 NULL 的行）。 | [第 8 章](第08章_聚合与分组.md) |
| `COUNT(列)` | 数这一列**非空值**的个数，NULL 会被跳过；和 `COUNT(*)` 的差别是经典考点。 | [第 8 章](第08章_聚合与分组.md) |
| `SUM` / `AVG` / `MAX` / `MIN` | 求和、平均值、最大值、最小值，都会自动跳过 NULL——统计口径要想清楚。 | [第 8 章](第08章_聚合与分组.md) |
| `GROUP BY` | 把行按某列归堆、每组压缩成一行输出。**铁律：SELECT 里的非聚合列必须出现在 GROUP BY 里。** | [第 8 章](第08章_聚合与分组.md) |
| `HAVING` | 筛**组**（分组之后），可以用聚合函数；和筛行的 `WHERE` 各司其职。 | [第 8 章](第08章_聚合与分组.md) |
| 执行顺序 | `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`；先拿表、再筛行、再分组、再算 SELECT。 | [第 8 章](第08章_聚合与分组.md) |
| `GROUP BY 1` | 按输出结果第 1 列分组的语法糖，配合 `date_trunc` 做按月统计很好用。 | [第 10 章](第10章_NULL与常用函数.md) |

| 整数除法陷阱 | 整数除整数得整数：`7 / 2` = 3 而不是 3.5；算比率要写成 `7 / 2.0` 或先 `* 100.0`。 | [第 8 章](第08章_聚合与分组.md) |
| `JOIN` | 沿外键把多张表按编号"拼"回来的操作，是 SQL 精通与否的分水岭。 | [第 9 章](第09章_多表连接JOIN.md) |
| `ON` | JOIN 的连接条件，说明"哪一列对哪一列"：`ON e.student_id = s.student_id`。 | [第 9 章](第09章_多表连接JOIN.md) |
| 表别名 | 多表查询时给表起的短名（`AS s`），列名冲突时必须用它消歧：`s.student_id`。 | [第 9 章](第09章_多表连接JOIN.md) |

| `RIGHT JOIN` | 右表全保留，与 LEFT 对称；实践中少用，习惯改写成 LEFT。 | [第 9 章](第09章_多表连接JOIN.md) |
| `FULL JOIN` | 两边都全保留，各自配不上的都补 NULL（并集）。 | [第 9 章](第09章_多表连接JOIN.md) |
| 自连接（Self Join） | 一张表当两张用，查"表内行与行的关系"：同院系同事、组织架构上下级。 | [第 9 章](第09章_多表连接JOIN.md) |
| 链式外键 / 多表 JOIN | 顺着外键一路连下去，四表 JOIN 出"成绩单"；理论上可以一直连。 | [第 9 章](第09章_多表连接JOIN.md) |
| `CROSS JOIN` / 笛卡尔积 | 所有行两两配对；`JOIN` 忘写 `ON` 就会发生，两张千行表能炸出一百万行。 | [第 9 章](第09章_多表连接JOIN.md) |
| `UNION` / `UNION ALL` | **上下拼行**（和左右拼列的 JOIN 相对）；两个 SELECT 列数与类型必须一致，`UNION` 去重、`UNION ALL` 不去重更快。 | [第 9 章](第09章_多表连接JOIN.md) |
| 子查询（Subquery） | 查询里的查询，有三种位置：当值用、当集合用、当临时表用。 | [第 11 章](第11章_子查询_CTE与窗口函数.md) |

| `FIRST_VALUE` / `LAST_VALUE` / `NTH_VALUE` | 取窗口内第一个、最后一个、第 n 个值。 | [第 11 章](第11章_子查询_CTE与窗口函数.md) |

| `COALESCE` | "第一个非空值"，给 NULL 兜底：`COALESCE(city, '未填写')`。 | [第 10 章](第10章_NULL与常用函数.md) |

| 空字符串（`''`） | 和 NULL 完全不同：空字符串是"已知内容为空"，NULL 是"未知"。 | [第 10 章](第10章_NULL与常用函数.md) |
| `<>` 漏掉 NULL 行 | `city <> '北京'` 不会返回 city 为 NULL 的行，因为结果是 NULL 不是 true；要补 `OR city IS NULL`。 | [第 10 章](第10章_NULL与常用函数.md) |
| `CURRENT_DATE` / `now()` | 今天（date）/ 此刻（timestamptz）两个动态取值函数。 | [第 10 章](第10章_NULL与常用函数.md) |

## A.5 事务与并发

本类按**从概念到现象**排列：先事务与 ACID，再隔离级别，再锁与 MVCC。

| 术语 | 大白话解释 | 首次出现章节 |
|---|---|---|
| 事务（Transaction） | 把多条 SQL 捆成一个"要么全成、要么全不做"的原子单元；转账就是教科书例子。 | [第 12 章](第12章_事务.md) |
| ACID | 事务四大特性的缩写：原子性、一致性、隔离性、持久性。 | [第 12 章](第12章_事务.md) |
| 原子性（Atomicity） | 全部成功或全部回滚，"一荣俱荣，一损俱损"。 | [第 12 章](第12章_事务.md) |
| 一致性（Consistency） | 事务前后数据满足所有约束，"账目永远平"。 | [第 12 章](第12章_事务.md) |
| 隔离性（Isolation） | 并发事务互不干扰，"各干各的，像独占数据库"；程度可以调。 | [第 12 章](第12章_事务.md) |
| 持久性（Durability） | COMMIT 之后的修改断电也不丢，"落袋为安"。 | [第 12 章](第12章_事务.md) |
| `BEGIN` | 开启一个事务；也可写 `BEGIN TRANSACTION;` 或 `START TRANSACTION;`。 | [第 12 章](第12章_事务.md) |
| `COMMIT` | 定案提交，之后不可再 ROLLBACK。 | [第 12 章](第12章_事务.md) |
| `ROLLBACK` | 反悔回滚，回到 BEGIN 之前的状态。 | [第 12 章](第12章_事务.md) |
| 自动提交（Autocommit） | 不写 `BEGIN` 时每条语句自成一个微型事务、执行即提交；这就是危险操作要手动包事务的原因。 | [第 12 章](第12章_事务.md) |
| DDL 可回滚 | PG 的特色：建表删表也能放进事务回滚；MySQL 大部分场景不行——这是 PG 的一大优势。 | [第 12 章](第12章_事务.md) |
| 事务提示符 `*` | psql 里提示符从 `=>` 变成 `=*>`，提醒你"手里有未提交的事务"。 | [第 12 章](第12章_事务.md) |
| 防呆模板 | `BEGIN;` → 危险操作 → `SELECT` 检查影响范围 → `COMMIT;`（或 `ROLLBACK;`）。 | [第 12 章](第12章_事务.md) |
| 隔离级别（Isolation Level） | 并发事务之间"互不干扰到什么程度"的档位；在 `BEGIN` 时指定。 | [第 12 章](第12章_事务.md) |
| 快照（Snapshot） | 事务或语句开始时"拍下"的数据视图，读操作按快照选版本看。 | [第 12 章](第12章_事务.md) |
| `READ COMMITTED` | PG **默认**隔离级别：每条语句开始时拍一张最新快照，所以同一事务内两次读可能不同（不可重复读）。 | [第 12 章](第12章_事务.md) |
| `REPEATABLE READ` | 事务开始时拍快照，之后读数恒定；代价是要改别人已改的数据会报 `could not serialize access due to concurrent update`，只能回滚重来。 | [第 12 章](第12章_事务.md) |
| `SERIALIZABLE` | 最严格的隔离级别，冲突多、需要重试逻辑。 | [第 12 章](第12章_事务.md) |
| `READ UNCOMMITTED` | 标准里的最宽松档；**PG 不支持，等同 READ COMMITTED**。 | [第 12 章](第12章_事务.md) |
| `SHOW transaction_isolation` | 查看当前会话的隔离级别。 | [第 12 章](第12章_事务.md) |
| 脏读（Dirty Read） | 读到了别人尚未提交的数据；PG 各档隔离级别下都不可能发生。 | [第 12 章](第12章_事务.md) |
| 不可重复读（Non-repeatable Read） | 同一事务里两次读同一行得到不同结果；READ COMMITTED 下可能发生。 | [第 12 章](第12章_事务.md) |
| 幻读（Phantom Read） | 同一事务里两次查询"行数"变了；PG 下 REPEATABLE READ 也已排除（快照隔离比标准更严格）。 | [第 12 章](第12章_事务.md) |
| 行锁（Row-Level Lock） | `UPDATE`/`DELETE` 会给目标行加锁，另一个事务改同一行必须等。 | [第 12 章](第12章_事务.md) |
| 表锁 | 用 `LOCK TABLE 表 IN ... MODE;` 显式加的锁，按模式限制他人读写。 | [第 12 章](第12章_事务.md) |
| `lock_timeout` | 设置等锁的最长时间；PG 默认不设，会一直等下去：`SET lock_timeout = '5s';`。 | [第 12 章](第12章_事务.md) |
| 死锁（Deadlock） | A 锁行 1 等 B 的行 2，B 锁行 2 等 A 的行 1，互相等；PG 约 1 秒（`deadlock_timeout`）后自动检测并牺牲一个事务。 | [第 12 章](第12章_事务.md) |
| `deadlock_timeout` | 死锁检测的等待阈值，默认约 1 秒。 | [第 12 章](第12章_事务.md) |
| MVCC（多版本并发控制，Multi-Version Concurrency Control） | 修改会创建数据行的新版本，读者按快照选版本看，所以**读不阻塞写、写不阻塞读**——PG 高并发的根基。 | [第 12 章](第12章_事务.md) |
| `SAVEPOINT` | 事务里的"存档点"；`ROLLBACK TO sp1` 只撤销到存档点，之前的改动保留。 | [第 12 章](第12章_事务.md) |
| `pg_locks` | 查看当前锁情况的系统视图，锁住了想知道谁锁的查它。 | [第 12 章](第12章_事务.md) |
| `pg_stat_activity` | 看"谁在跑什么、谁在等"的视图，是排查卡顿的第一现场。 | [第 12 章](第12章_事务.md) |
| `pg_terminate_backend(pid)` | 管理员用来终结某个卡死会话的函数。 | [第 12 章](第12章_事务.md) |
| 写冲突 | 两个事务改同一行时后写者要等；REPEATABLE READ 下甚至直接报序列化错误。 | [第 12 章](第12章_事务.md) |

## A.6 索引与性能

本类按**"是什么 → 怎么看 → 怎么调"**排列。

| 术语 | 大白话解释 | 首次出现章节 |
|---|---|---|
| 索引（Index） | 提前建好的"字典部首目录"，把列值有序组织起来，查找不用一行行翻。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 顺序扫描 / 全表扫描（Seq Scan, Sequential Scan） | 从第一行扫到最后一行，最笨但最可靠；小表正常，大表是灾难。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 索引扫描（Index Scan） | 走索引定位数据，`O(log n)` 步搞定，4800 万行只需约 26 步。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| B-tree（平衡多路搜索树） | 默认的索引类型，把列值有序组织成树；等值、范围、排序都擅长，99% 的场合用它。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `CREATE INDEX` | 建索引的语句：`CREATE INDEX idx_名字 ON 表(列);`。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 复合索引 / 多列索引 | 按多列一起排的索引，如 `(student_id, course_id)`；**列顺序很重要**，按查询条件顺序设计。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 唯一索引（Unique Index） | 既保证唯一又加速；它和 `UNIQUE` 约束背后是同一个东西。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 表达式索引 | 把"计算结果"建进索引，如 `(lower(name))`，让函数包裹的查询也能走索引。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 外键不会自动建索引 | 重要事实：主键和 UNIQUE 约束自动带索引，**外键列要手动建**（教程给 enrollments 两列都建了）。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 索引自动维护 | INSERT/UPDATE/DELETE 时同步更新索引，所以索引让读变快、写略变慢、占额外磁盘——**不是越多越好**。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `EXPLAIN` | 显示**执行计划**（数据库打算怎么找数据），不会真的执行。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `EXPLAIN ANALYZE` | 真正执行并附带**实际耗时**；因为会真跑，对 UPDATE/DELETE 用它会真改数据（调试时换成同条件的 SELECT）。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 执行计划（Execution Plan） | EXPLAIN 输出的那棵树，说明先扫哪张表、用什么方式、怎么拼。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `Index Cond` | 执行计划里"索引中实际用的条件"，出现它说明索引用上了。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `Filter` | 索引之外还要逐行过滤的条件，通常意味着索引没能覆盖全部筛选。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `Nested Loop` / `Hash Join` | 两表怎么拼的两种方式；小表常用嵌套循环，大表常用哈希连接。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `rows=` 预估与实际 | 预估行数和实际行数差很远，说明统计信息过期，需要 ANALYZE。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `Execution Time` | 执行计划里的真实耗时，判断快慢的直接依据。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 优化三步循环 | `EXPLAIN ANALYZE` → 找到最贵的节点 → 改（加索引/改写）→ 再 `EXPLAIN ANALYZE` 对比。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 索引失效三宗罪 | 列上做运算、函数包裹（除非表达式索引）、隐式类型转换——都会让索引用不上。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 隐式类型转换 | `WHERE user_no::text = '500'` 这类写法会毁掉索引。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `LIKE` 与索引 | `LIKE '王%'`（后置通配符）能走索引；`LIKE '%王'`（前置通配符）走不了。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 索引类型选型 | `btree` 默认、`hash` 只有等值、`gin` 数组/JSONB/全文、`gist` 地理范围、`brin` 超大表 + 物理有序列。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| keyset 分页 | 深分页的替代写法：用 `WHERE id > 上页末尾id LIMIT 20` 代替 `OFFSET 100000`。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `COPY` | 批量导入数据的命令，一万条 INSERT 合成一条多值 INSERT 或用它，快一个数量级。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 统计信息 | 数据库用来估行数的数据，过期会让执行计划跑偏；管理员可跑 `ANALYZE 表名;` 刷新（大批量导入后常做）。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `VACUUM` | MVCC 的清洁工，回收被删/被更新后残留的旧版本行。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `autovacuum` | 后台自动运行的清理进程，日常无需手动干预。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `VACUUM FULL` | 物理重组并把空间归还磁盘，会锁全表，只在维护窗口用。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `dead tuples` / 表膨胀 | 未被回收的旧版本行计数异常增长，说明 autovacuum 跟不上了。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| `shared_buffers` / `work_mem` | 影响性能的系统级配置参数（进阶，先把 SQL 层做好再动）。 | [第 13 章](第13章_索引与EXPLAIN.md) |
| 连接池（Connection Pool） | 复用数据库连接、避免频繁建连的开销。（进阶，见[第 16 章](第16章_综合项目_学生选课管理系统.md)进阶路线） | [第 16 章](第16章_综合项目_学生选课管理系统.md) |
| `pg_stat_statements` | 找慢查询的扩展工具。（进阶，见[第 16 章](第16章_综合项目_学生选课管理系统.md)进阶路线） | [第 16 章](第16章_综合项目_学生选课管理系统.md) |

| 术语 | 大白话解释 | 首次出现章节 |

| 权限矩阵 | 表上有 `SELECT`/`INSERT`/`UPDATE`/`DELETE`/`TRUNCATE`/`REFERENCES`/`TRIGGER`/`ALL`；模式上有 `USAGE`/`CREATE`；库上有 `CONNECT`/`CREATE`/`TEMPORARY`。 | [第 15 章](第15章_用户权限与安全.md) |
| `USAGE`（模式的） | 允许"路过"这个模式去访问里面的对象；**没有它，就算授权了表也访问不到**。 | [第 15 章](第15章_用户权限与安全.md) |

| SQL 注入（SQL Injection） | 把用户输入拼进 SQL 字符串，输入里夹带的 SQL 就会被执行——所有数据库的头号敌人。 | [第 15 章](第15章_用户权限与安全.md) |

| 最小权限原则 | 每个应用/每人一个独立账号，只授权它真正需要的表和操作；绝不用 `postgres` 超管连应用。 | [第 15 章](第15章_用户权限与安全.md) |

## A.10 易混淆术语辨析

这些词看着像、用着容易错。**不用背，遇到分不清的时候回来对一眼表格**。

### database vs schema

| | 数据库（Database） | 模式（Schema） |
|---|---|---|
| 类比 | 你家的文件柜 | 柜子里的抽屉 |
| 在层级里 | 服务器下面那一层 | 数据库下面那一层 |
| 例子 | `beginner_pg` | `school`、`public`、`library` |
| 能否同名共存 | 同一服务器上库名唯一 | 不同库里可以有同名模式 |
| MySQL 里 | —— | `database` 和 `schema` 是同义词，**PG 里是两层不同结构** |

### 行 vs 列（record vs field）

| | 行（Row / 记录 Record） | 列（Column / 字段 Field） |
|---|---|---|
| 方向 | 横着的一整条 | 竖着的一整项 |
| 内容 | 一条完整的信息（一个学生） | 一类信息（所有人的姓名） |
| 类型 | 每列各有自己的类型，同一行的各列类型可以不同 | 整列共用同一个数据类型 |

### 主键 vs 外键 vs 唯一约束

| | 主键（PRIMARY KEY） | 唯一约束（UNIQUE） | 外键（FOREIGN KEY） |
|---|---|---|---|
| 管什么 | 唯一标识本表的行 | 这一列的值不许重复 | 本列值必须已在对方表存在 |
| 能否有多个 | 一张表只能一个 | 可以有多个 | 可以有多个 |
| 允许 NULL | 不允许 | 允许 | 取决于列本身是否 NOT NULL |
| 自动建索引 | 是 | 是 | **否，外键不会自动建索引** |
| 类比 | 身份证 | 手机号不能撞号 | 指向别的表的指针 |

### NULL vs 空字符串 `''`

| | `NULL` | 空字符串 `''` |
|---|---|---|
| 语义 | "未知"，不知道有没有 | "已知：内容为空" |
| `IS NULL` 判断 | true | false |
| `length()` | 返回 NULL | 返回 0 |
| 比较结果 | 和任何值比较都得 NULL | 按普通字符串比较 |
| 清洗要点 | 导入数据时"看起来空白"的格子可能是 `''`、NULL、甚至 `' '`，三种都要想到 | 详见 [第 10 章](第10章_NULL与常用函数.md) |

### DELETE vs TRUNCATE vs DROP

| | `DELETE FROM 表;` | `TRUNCATE 表;` | `DROP TABLE 表;` |
|---|---|---|---|
| 删什么 | 行（可带 WHERE 挑着删） | 全部行 | **表本身连结构一起** |
| 支持 WHERE | 支持 | 不支持 | —— |
| 速度 | 逐行删，大表慢 | 秒清，重置存储 | 瞬间 |
| 自增序列 | 继续往下发号 | 重置回 1 | 表都没了 |
| 事后还能用表吗 | 能 | 能（结构保留） | 不能 |
| 类型 | DML（数据） | 偏 DDL 行为 | DDL（结构） |

### WHERE vs HAVING

| | `WHERE` | `HAVING` |
|---|---|---|
| 筛什么 | 筛**行** | 筛**组** |
| 时机 | 分组**之前** | 分组**之后** |
| 能否用聚合函数 | 不能（报 `aggregate functions are not allowed in WHERE`） | 能 |
| 典型写法 | `WHERE score >= 60` | `HAVING AVG(score) > 80` |

### JOIN 四种类型

| 类型 | 保留谁 | 结果 | 集合直觉 |
|---|---|---|---|
| `INNER JOIN` | 只留两边都配得上的 | 1、4 消失 | 交集 |
| `LEFT JOIN` | 左表全保留 | 右边配不上补 NULL | 左整圆 |
| `RIGHT JOIN` | 右表全保留 | 左边配不上补 NULL | 右整圆 |
| `FULL JOIN` | 两边都全保留 | 两边配不上的都补 NULL | 并集 |

### READ COMMITTED vs REPEATABLE READ

| | `READ COMMITTED`（PG 默认） | `REPEATABLE READ` |
|---|---|---|
| 快照时机 | **每条语句**开始时拍一张 | **整个事务**开始时拍一张 |
| 同一事务内两次读 | 可能读到不同结果（不可重复读） | 恒定不变 |
| 要改别人已改的数据 | 等着，然后接着改 | 报 `could not serialize access due to concurrent update`，只能回滚重来 |
| 适用 | 90% 场景 | 报表、需要一致性读取的场景 |

### 顺序扫描 vs 索引扫描

| | Seq Scan（全表扫描） | Index Scan（索引扫描） |
|---|---|---|
| 怎么找 | 从第一行翻到最后一行 | 走索引目录，`O(log n)` 步定位 |
| 48 行小表 | 完全没问题 | 不一定比全扫快 |
| 4800 万行大表 | 平均要翻 2400 万行 | 约 26 步 |
| 在 EXPLAIN 里的样子 | `Seq Scan on 表名` | `Index Scan using idx_...` |

### `COUNT(*)` vs `COUNT(列)`

| | `COUNT(*)` | `COUNT(列)` |
|---|---|---|
| 数什么 | 行数 | 该列**非空值**的个数 |
| 对 NULL | 全部都数 | 跳过 NULL |
| 教程例子 | 42 条选课记录全算 | 39 条有成绩，3 条在读未考不计 |

### `IN` vs `EXISTS`

| | `IN (子查询)` | `EXISTS (子查询)` |
|---|---|---|
| 关心什么 | 值在不在这个集合里 | 子查询有没有行 |
| 遇 NULL | `NOT IN` 遇 NULL 会全军覆没 | 不受 NULL 影响 |
| 大表表现 | 可能要把整个子查询结果取回 | 找到第一行即短路返回 |
| 建议 | 小集合、值明确 | 大表关联、有 NULL 风险时优先 |

### 事务 vs 自动提交

| | 手动事务（`BEGIN` 开头） | 自动提交（不写 BEGIN） |
|---|---|---|
| 每条语句 | 属于同一个事务 | 自成一个微型事务，执行即提交 |
| 能后悔吗 | 能，`ROLLBACK` 撤销 | **不能**，这就是不带 WHERE 的 UPDATE 没有后悔药的原因 |
| psql 提示符 | 变成 `=*>` | 保持 `=>` |

### `pg_dump` vs `pg_dumpall` vs `pg_basebackup`

| | `pg_dump` | `pg_dumpall` | `pg_basebackup` |
|---|---|---|---|
| 备什么 | **单个数据库** | **整个集群**（含角色、表空间） | 物理全量 + WAL |
| 格式 | SQL 文本 / 自定义 | SQL 文本 | 二进制 |
| 含角色密码吗 | **不含**（角色是集群级对象） | 含（`--globals-only`） | —— |
| 典型场景 | 日常备份、迁移（本教程主角） | 服务器整体搬迁 | 建立从库、PITR（进阶） |

### 串行 vs 并行恢复（`-j`）

| | 跑 `pg_restore -j 4` | 不写 `-j` |
|---|---|---|
| 任务数 | 4 个并行任务同时恢复 | 单线程顺序恢复 |
| 需要什么格式 | 只能配**自定义格式** `-Fc` 的备份 | SQL 文本也可以 |
| 谁快 | 大库快很多 | 慢 |

### 表锁 vs 行锁

| | 行锁 | 表锁 |
|---|---|---|
| 谁持有 | `UPDATE`/`DELETE` 自动给目标行加 | 用 `LOCK TABLE ... IN ... MODE;` 显式加 |
| 影响范围 | 只挡改同一行的其他事务 | 按模式限制他人读写整张表 |
| 常见度 | 日常最常遇到 | 特殊场景显式使用 |

### Linux 账号 vs 数据库账号

| | Linux 账号（如 `ubuntu`） | 数据库账号（如 `student_pg`） |
|---|---|---|
| 决定 | 能否登录这台服务器、能碰哪些系统文件 | 登录服务器之后能否连数据库、能查哪些表 |
| 出现在哪 | SSH 会话配置的 Username 字段 | `psql -U` 参数、pgAdmin 的 Username 字段 |
| 关系 | 两套体系完全独立：能 SSH 上服务器 ≠ 能连数据库 | 反之亦然 |

## A.11 术语速记口诀

把术语串成几句话，比零散记忆牢固得多。这几句呼应[第 1 章](第01章_数据库基础概念.md)的概念地图，读完一遍再往下读一遍。

**层级口诀：**
> 服务器装 PG，库里分模式，模式放表，表有行列。
> `服务器 → beginner_pg → school → 五张表`——忘了自己在哪一层，就先念这一句。

**身份口诀：**
> 主键是行身份证，外键是指向别人的指针，唯一约束是"不许撞号"，CHECK 是"业务法律"。
> 主键管唯一，外键管引用，两者都要，一个都不能少。

**数据入口口诀：**
> 一类实体一张表，关系用编号来表达；多对多要中间表，正好就是 `enrollments`。

**查询口诀：**
> SELECT 取列、FROM 拿表、WHERE 筛行、GROUP BY 归堆、HAVING 筛组、ORDER BY 排队、LIMIT 截断。
> 书写顺序就是这个顺序，执行顺序是 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`。
> 筛行用 WHERE，筛组用 HAVING；裸列必须进 GROUP BY。

**NULL 口诀：**
> NULL 是"未知"不是"空"，判断只能 `IS NULL`；`<>` 会漏掉 NULL 行，`NOT IN` 遇 NULL 会全空。

**JOIN 口诀：**
> INNER 要交集，LEFT 保左表，RIGHT 保右表，FULL 全都要，配不上补 NULL。
> LEFT JOIN 加 IS NULL，就是找"没有"的行。

**窗口函数口诀：**
> GROUP BY 折叠行，窗口函数贴标签；`函数 OVER (PARTITION BY ... ORDER BY ...)`，行数一行不少。
> 窗口函数只能进 SELECT 和 ORDER BY，要按它筛结果，外面再包一层。

**事务口诀：**
> BEGIN 开、COMMIT 定案、ROLLBACK 反悔；ACID 四个字：原子、一致、隔离、持久。
> 不写 BEGIN 就是自动提交，删错没有后悔药——危险操作先 SELECT 预览、再包事务。
> 默认 READ COMMITTED（每语句一快照），要整事务一致就 REPEATABLE READ。

**索引口诀：**
> 索引是字典部首目录，主键唯一自动有，**外键要自己建**。
> 列上做运算、函数包着列、隐式转类型——索引全部失效。
> 优化先看 `EXPLAIN ANALYZE`，找到最贵的节点再动手。

**备份口诀：**
> `pg_dump` 备单库，`pg_dumpall` 备整集群；自定义格式 `-Fc` 压缩能并行。
> 备份不带角色，恢复后连不上别慌，是少了 `CREATE ROLE`。
> **没做过恢复演练的备份等于没备份。**

**权限口诀：**
> 先过连接关（`pg_hba.conf` + `LOGIN` + `CONNECT`），再过对象关（模式 `USAGE` + 表权限）；
> 两关缺一个都 `permission denied`。
> GRANT 给、REVOKE 收、PUBLIC 是"所有人"；组角色 + 成员继承才是团队正解。
> 参数化查询根治 SQL 注入，应用账号最小权限是最后的保险丝。

**最后一句：**
> 报错不是故障，是数据库在替你挡脏数据——**报错是朋友**。
