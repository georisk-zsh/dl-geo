单行查询回答"谁、哪个"；聚合回答"多少、平均、最高"。本章是数据分析的起点。

## 8.1 聚合函数：把一摞行压缩成一个数

| 函数 | 作用 | 对 NULL 的态度 |
|---|---|---|
| `COUNT(*)` | 数行数 | **全部都数**（包括全 NULL 行） |
| `COUNT(列)` | 数该列非空值的个数 | **跳过 NULL** |
| `SUM(列)` | 求和 | 跳过 NULL |
| `AVG(列)` | 平均值 | 跳过 NULL |
| `MAX(列)` / `MIN(列)` | 最大 / 最小 | 跳过 NULL |

```sql
SELECT COUNT(*)   FROM school.students;              -- 学生总数：15
SELECT COUNT(*)   FROM school.enrollments;           -- 选课记录总数：42
SELECT COUNT(score) FROM school.enrollments;         -- 有成绩的记录数（在读未考的 NULL 不算）
SELECT AVG(score), MAX(score), MIN(score) FROM school.enrollments;
```

> **`COUNT(*)` vs `COUNT(列)` 是经典考点**：数"记录条数"用前者，数"该字段实际填了的"用后者。例：本教程 42 条选课记录里 39 条有成绩，`COUNT(*)=42`、`COUNT(score)=39`（差的 3 条是"在读未考"）。

> **AVG 的 NULL 语义**：`AVG(score)` 是"有成绩的记录的平均"，分母不含 NULL 行——统计口径要想清楚（未考试算 0 分还是不算？两种口径结果完全不同）。

## 8.2 分组：GROUP BY

"每个城市有多少学生"——先按城市分组，再对每组 COUNT：

```sql
SELECT city, COUNT(*) AS 学生人数
FROM school.students
GROUP BY city
ORDER BY 学生人数 DESC;
```

```text
 city | 学生人数
──────+──────────
 北京 |        3
 上海 |        1
 广州 |        1
 ...  |        ...
(若干行，含 city 为 NULL 的一组)
```

**执行模型（务必理解）**：GROUP BY city 把 15 行按城市归堆，每组压缩成一行输出。所以——

> **铁律：SELECT 里出现的非聚合列，必须出现在 GROUP BY 里。**

```sql
SELECT city, name, COUNT(*) FROM school.students GROUP BY city;   -- ✗
ERROR: column "students.name" must appear in the GROUP BY clause
```

报错原因：city 分组后"北京组"里有 3 个人，`name` 该显示谁？数据库不知道，所以直接拒绝。GROUP BY 做不到"每组内取某一行"——那是窗口函数的工作（[第 11 章](第11章_子查询_CTE与窗口函数.md)）。

**分组前先筛 vs 分组后筛**——子句顺序与执行顺序（背下来）：

```text
书写顺序：SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
         （先拿哪些表 → 先筛掉哪些行 → 再分组 → 筛掉哪些组 → 最后才算 SELECT 和排序）
```

## 8.3 WHERE vs HAVING

- **WHERE** 筛**行**（分组之前，不能用聚合函数）；
- **HAVING** 筛**组**（分组之后，可以用聚合函数）。

```sql
-- 每门课的选课人数和平均分，只保留选课人数 >= 5 的课，按平均分降序
SELECT c.course_name,
       COUNT(*)      AS 选课人数,
       ROUND(AVG(e.score), 1) AS 平均分
FROM school.courses c
JOIN school.enrollments e ON e.course_id = c.course_id
GROUP BY c.course_name
HAVING COUNT(*) >= 5
ORDER BY 平均分 DESC;
```

> 例子里出现了 JOIN，是下一章主角，先照抄感受。注意 `c.` 和 `e.` 前缀——两张表都有 `course_id` 时必须写清"谁的"。

经典对照："平均分大于 80 的课程"：

```sql
HAVING AVG(score) > 80        -- ✓ 组级条件
WHERE AVG(score) > 80         -- ✗ ERROR: aggregate functions are not allowed in WHERE
```

## 8.4 按多列分组

```sql
-- 每个城市、每种性别的学生数
SELECT city, gender, COUNT(*)
FROM school.students
GROUP BY city, gender
ORDER BY city, gender;
```

组合的粒度 = 分组列的元组。"北京-女"一组、"上海-男"一组……组数变多、粒度变细。

## 8.5 GROUP BY + CASE WHEN：报表常用的"手工透视"

`CASE WHEN` 是 SQL 里的 if-else（[第 10 章](第10章_NULL与常用函数.md)细讲），配合 GROUP BY 能直接出报表：

```sql
-- 每门课的选课人数、及格人数、不及格人数（在读未考单独一列）
SELECT c.course_name,
       COUNT(*) AS 总人次,
       COUNT(*) FILTER (WHERE e.score >= 60)              AS 及格人次,
       COUNT(*) FILTER (WHERE e.score < 60)               AS 不及格人次,
       COUNT(*) FILTER (WHERE e.score IS NULL)            AS 在读未考
FROM school.courses c
JOIN school.enrollments e ON e.course_id = c.course_id
GROUP BY c.course_name
ORDER BY 总人次 DESC;
```

`COUNT(*) FILTER (WHERE 条件)` 是 PostgreSQL 的优雅扩展，比传统 `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` 好读得多，两者结果一致。

## 8.6 整数除法与比率陷阱（常见坑）

```sql
SELECT 7 / 2;          -- = 3 ！整数除整数得整数
SELECT 7 / 2.0;        -- = 3.5
SELECT ROUND(100.0 * COUNT(*) FILTER (WHERE score >= 60) / COUNT(*), 1) AS 及格率
FROM school.enrollments;     -- 算比率先乘 100.0，强制小数
```

## 8.7 常用套路总结

| 业务问题 | 套路 |
|---|---|
| 总共多少条记录 | `COUNT(*)`，无 GROUP BY |
| 每个类目多少条 | `GROUP BY 类目 + COUNT(*)` |
| 每个类目的平均值/最大值 | `GROUP BY 类目 + AVG/MAX` |
| 平均值超过 X 的类目 | `GROUP BY + HAVING AVG(...) > X` |
| 排名前 N 的类目 | `GROUP BY + ORDER BY 聚合 DESC + LIMIT N` |
| 每类目的多状态计数 | `COUNT(*) FILTER (WHERE ...)` |

## 本章小结

- 聚合函数把多行压成一个数；`COUNT(*)` 数行、`COUNT(列)` 数非空；AVG/SUM 自动跳过 NULL（口径要想清）；
- GROUP BY 把行归堆，每组出一行；**SELECT 的裸列必须在 GROUP BY 里**；
- WHERE 筛行（分组前）、HAVING 筛组（分组后），执行顺序 FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT；
- `FILTER (WHERE ...)` 做条件计数；算比率先乘 `100.0` 避免整数除法截断。
