表是数据库真正的"资产"。本章学习：选对数据类型、加上各种约束、亲手创建选课系统的五张表。

## 5.1 设计先行：选课系统需要哪几张表？

回顾[第 1 章](第01章_数据库基础概念.md)的思路——**一类"实体"一张表，关系用外键表达**。学生选课业务的最小完整设计：

```text
departments（院系）──┐
                     ├── teachers（教师，属于某院系）
students（学生）─────┤
                     ├── courses（课程，由某教师开）──┐
                     │                                ├── enrollments（选课成绩）
                     └────────────────────────────────┘
```

五张表、四条外键关系。每张表的核心字段：

| 表 | 字段 | 为什么 |
|---|---|---|
| departments | dept_id, dept_name | 院系名称 |
| teachers | teacher_id, name, title, hire_date, dept_id | 教师信息 + 所属院系（外键） |
| students | student_id, student_no, name, gender, birth_date, city, enrolled_on | 学生信息 |
| courses | course_id, course_name, teacher_id, credit, hours | 课程 + 开课教师（外键） |
| enrollments | enrollment_id, student_id, course_id, enrolled_on, score | 谁选了哪门课考了多少分（双外键） |

## 5.2 最常用数据类型速查

**选类型的原则：够用就好、语义准确。** 类型决定了存储方式、可参与的运算、以及能加什么约束。

### 数值类

| 类型 | 用途 | 说明 |
|---|---|---|
| `integer` (int4) | 整数：年龄、数量、id | ±21 亿，日常首选 |
| `bigint` (int8) | 大整数：订单号、日志 id | ±9.2×10¹⁸ |
| `smallint` (int2) | 小整数：状态码 | 节省空间，少用 |
| `numeric(p, s)` / `decimal` | **精确小数：钱、成绩** | p 总位数，s 小数位；`numeric(5,1)` 能存 `-9999.9` |
| `real` / `double precision` | 近似小数：科学计算 | 有浮点误差，**禁止存钱和成绩** |

> ⚠️ 经典陷阱：`0.1 + 0.2` 用浮点类型算出 `0.30000000000000004`。凡是要"分毫不差"的数值（金额、分数、利率）一律 `numeric`。

### 文本类

| 类型 | 说明 |
|---|---|
| `varchar(n)` | 变长文本，最多 n 个字符（**n 是字符数不是字节数**，中文一个字算一个） |
| `text` | 变长文本，无长度上限 |
| `char(n)` | 定长，不足自动补空格（基本只在固定编码场景用） |

> PG 中 `varchar` 和 `text` 性能几乎无差别；长度限制的意义是**业务约束**而不是性能。名字用 `varchar(40)`，简介用 `text` 即可。

### 日期时间类

| 类型 | 存什么 | 例子 |
|---|---|---|
| `date` | 只有日期 | `2025-09-01` |
| `time` | 只有时刻 | `08:30:00` |
| `timestamp` | 日期+时刻 | `2025-09-01 08:30:00` |
| `timestamptz` | 日期+时刻+时区 | 推荐：存入时自动转 UTC，读出时按会话时区显示 |
| `interval` | 时间长度 | `INTERVAL '2 days'`（[第 10 章](第10章_NULL与常用函数.md)用） |

> 经验：**记录"发生了什么"的时间一律 `timestamptz`**（注册时间、下单时间、日志时间），只有纯"日期"概念（生日、开学日期）才用 `date`。

### 布尔与特殊

| 类型/值 | 说明 |
|---|---|
| `boolean` | 只有三个值：`true` / `false` / `NULL` |
| `NULL` | "未知/不存在"，不是 0 也不是空字符串（[第 10 章](第10章_NULL与常用函数.md)专讲） |
| `uuid` | 全局唯一标识符，分布式系统常用 |
| `jsonb` | JSON 文档（进阶，知道存在即可） |

## 5.3 自增主键：GENERATED ALWAYS AS IDENTITY

主键最常见的形式是"自增整数"。现代 PostgreSQL 写法：

```sql
CREATE TABLE school.students (
    student_id  integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    ...
);
```

- `GENERATED ALWAYS`：**永远由数据库分配编号**，你手工插值会被拒绝（防止编号被打乱）；
- `GENERATED BY DEFAULT`：默认自增，但也允许手工指定（迁移数据时用）；
- 老教程里的 `SERIAL` 是历史写法，效果类似，**新项目请用 IDENTITY**（SQL 标准）。

插入数据时**不写** id 列，数据库自动发号：

```sql
INSERT INTO school.students (student_no, name) VALUES ('S2023001', '王小明');
-- student_id 自动为 1，下一条自动为 2……
```

## 5.4 约束全家福：给数据上"法律"

约束（Constraint）= 写入时自动执行的校验规则。**规则在数据库层，比任何应用层校验都可靠**——绕过应用直连数据库的脏数据照样被拦下。

### ① PRIMARY KEY —— 主键

```sql
student_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

自带"唯一 + 非空"，一张表只能有一个主键（可由多列组成，叫复合主键）。

### ② UNIQUE —— 唯一

```sql
student_no varchar(12) NOT NULL UNIQUE      -- 学号不许重复
```

与主键的区别：一张表可以有多个 UNIQUE 列，且允许 NULL（主键不行）。适合"身份证号、手机号、学号"这类"不是主键但不能重"的列。

### ③ NOT NULL —— 非空

```sql
name varchar(40) NOT NULL      -- 姓名必填
```

### ④ CHECK —— 自定义校验

```sql
score numeric(5,1) CHECK (score BETWEEN 0 AND 100),        -- 成绩 0~100
gender char(1)   CHECK (gender IN ('M', 'F'))              -- 性别只许 M/F
```

任何返回 true 的布尔表达式都可以。**把业务规则写进 CHECK**（分数范围、日期先后、数量为正），脏数据从源头断绝。

### ⑤ DEFAULT —— 默认值

```sql
enrolled_on date DEFAULT CURRENT_DATE      -- 不填就自动取今天
```

`CURRENT_DATE` / `now()` 这类"动态默认值"每次插入时求值。

### ⑥ FOREIGN KEY —— 外键

```sql
student_id integer NOT NULL REFERENCES school.students (student_id),
course_id  integer NOT NULL REFERENCES school.courses (course_id),
UNIQUE (student_id, course_id)     -- 同一学生同一课程只能选一次
```

含义：本列的值**必须已在**对方表的主键/唯一键中存在。插入"999 号学生的选课记录"会直接报错：

```text
ERROR: insert or update on table "enrollments" violates foreign key
constraint "enrollments_student_id_fkey"
DETAIL: Key (student_id)=(999) is not present in table "students".
```

**外键的 ON DELETE 行为**——对方表的行被删除时，本表引用它的行怎么办？

| 选项 | 效果 | 适用 |
|---|---|---|
| `NO ACTION`（默认） | 拒绝删除，报错 | 大多数场景，最安全 |
| `RESTRICT` | 同上（检查时机略不同） | 同上 |
| `CASCADE` | 跟着一起删 | "删除学生→连他的选课记录一起删" |
| `SET NULL` | 本列置为 NULL | "删除教师→课程的 teacher_id 置空（课程保留）" |
| `SET DEFAULT` | 置为列默认值 | 少用 |

```sql
teacher_id integer REFERENCES school.teachers(teacher_id) ON DELETE SET NULL,
--       删教师：课程保留，teacher_id 变 NULL（"暂无授课教师"）
student_id integer NOT NULL REFERENCES school.students(student_id) ON DELETE CASCADE
--       删学生：该学生的选课记录一并删除（选课记录离开学生无意义）
```

> 网上有些"性能流派"建议不用外键、只在应用层维护。**初学阶段请坚定地用外键**：它是数据一致性的保险丝，出问题时省下的排查时间远多于那点性能开销。

## 5.5 亲手建五张表

用 `student_pg` 连接后执行（或直接 `psql -U student_pg -d beginner_pg -f scripts/02_school_schema.sql`，脚本还会插入示例数据）：

```sql
beginner_pg=> CREATE TABLE school.departments (
    dept_id   integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    dept_name varchar(40) NOT NULL UNIQUE
);

beginner_pg=> CREATE TABLE school.teachers (
    teacher_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name       varchar(40) NOT NULL,
    title      varchar(20),
    hire_date  date,
    dept_id    integer REFERENCES school.departments(dept_id)
);

beginner_pg=> CREATE TABLE school.students (
    student_id  integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    student_no  varchar(12) NOT NULL UNIQUE,
    name        varchar(40) NOT NULL,
    gender      char(1) CHECK (gender IN ('M', 'F')),
    birth_date  date CHECK (birth_date > DATE '1980-01-01'),
    city        varchar(20),
    enrolled_on date DEFAULT CURRENT_DATE
);

beginner_pg=> CREATE TABLE school.courses (
    course_id   integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    course_name varchar(60) NOT NULL,
    teacher_id  integer REFERENCES school.teachers(teacher_id) ON DELETE SET NULL,
    credit      numeric(3,1) NOT NULL DEFAULT 2.0 CHECK (credit BETWEEN 0.5 AND 10),
    hours       integer DEFAULT 32 CHECK (hours > 0)
);

beginner_pg=> CREATE TABLE school.enrollments (
    enrollment_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    student_id    integer NOT NULL
        REFERENCES school.students(student_id) ON DELETE CASCADE,
    course_id     integer NOT NULL
        REFERENCES school.courses(course_id) ON DELETE CASCADE,
    enrolled_on   date NOT NULL DEFAULT CURRENT_DATE,
    score         numeric(5,1) CHECK (score BETWEEN 0 AND 100),
    UNIQUE (student_id, course_id)
);
```

## 5.6 验证与查看

```sql
beginner_pg=> \dt school.*
                    List of relations
 Schema |    Name     | Type  |   Owner
--------+-------------+-------+------------
 school | courses     | table | student_pg
 school | departments | table | student_pg
 school | enrollments | table | student_pg
 school | students    | table | student_pg
 school | teachers    | table | student_pg

beginner_pg=> \d school.enrollments
```

`\d` 输出会列出每列的类型、可空性、默认值，以及底部的外键、唯一约束——**整个表设计尽收眼底**，这是review 表结构的标准动作。

**故意触发几个约束，看看数据库怎么保护数据：**

```sql
beginner_pg=> INSERT INTO school.students (student_no, name, gender)
    VALUES ('S2023001', '重复学号', 'M');     -- 001 已存在
ERROR: duplicate key value violates unique constraint "students_student_no_key"

beginner_pg=> INSERT INTO school.students (student_no, name, gender, birth_date)
    VALUES ('S2023099', '穿越者', 'M', DATE '1900-01-01');
ERROR: new row for relation "students" violates check constraint "students_birth_date_check"
```

每一声报错都是数据库在替你挡脏数据——**报错是朋友**。

## 5.7 修改已有表：ALTER TABLE

表建好后改设计（字段加减、类型修改、约束追加）用 `ALTER TABLE`：

```sql
-- 加列
ALTER TABLE school.students ADD COLUMN email varchar(100);
-- 删列（该列数据一并删除，谨慎）
ALTER TABLE school.students DROP COLUMN email;
-- 改列类型（要求现有数据能兼容转换）
ALTER TABLE school.students ALTER COLUMN city TYPE varchar(30);
-- 加约束（对已有数据生效，已有违规数据会失败）
ALTER TABLE school.students ADD CONSTRAINT no_future
    CHECK (enrolled_on <= CURRENT_DATE);
-- 删约束（名字可从 \d 输出中抄）
ALTER TABLE school.students DROP CONSTRAINT no_future;
-- 改列名 / 表名
ALTER TABLE school.students RENAME COLUMN gender TO sex;
ALTER TABLE school.students RENAME TO student;
```

> 生产环境改表先备份（[第 14 章](第14章_备份与恢复.md)）并先在测试库演练。给"已有数据"的大表加 CHECK 约束会全表扫描验证，注意业务低峰执行。

## 5.8 删除表：DROP / TRUNCATE

```sql
DROP TABLE school.enrollments;         -- 连表带数据删除（外键引用它的表会阻止你）
TRUNCATE TABLE school.enrollments;     -- 只清空数据，保留表结构，速度快且重置自增
```

`TRUNCATE` 像是"把整张表瞬间倒空"，`DELETE FROM 表`（不带 WHERE，下一章讲）也能清空但逐行删除、较慢。两者都不进"回收站"，动手前三思。

## 本章小结

- 类型选择口诀：整数 id 用 `integer` IDENTITY、钱和成绩用 `numeric`、名字 `varchar(n)`、长文 `text`、纯日期 `date`、事件时间 `timestamptz`；
- 约束六件套：`PRIMARY KEY`（身份证）、`UNIQUE`（不重）、`NOT NULL`（必填）、`CHECK`（业务规则）、`DEFAULT`（默认值）、`FOREIGN KEY`（引用完整性，配 ON DELETE 策略）；
- 建表顺序：先被引用的表（departments → teachers/students → courses → enrollments），删除顺序相反；
- `\dt` 看表清单、`\d 表名` 看结构；`ALTER TABLE` 改结构、`DROP/TRUNCATE` 毁灭性操作先备份。
