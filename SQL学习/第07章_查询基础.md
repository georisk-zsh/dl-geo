从本章起进入 SQL 的灵魂领域——查询。SELECT 是你未来写得最多的语句，也是最容易"一招鲜吃遍天"的语句。

## 7.1 SELECT 的骨架：从哪儿取、取哪些列、要哪些行

```sql
SELECT 列1, 列2, ...        -- 取哪些列（投影）
FROM 表                     -- 从哪儿取
WHERE 条件                  -- 要哪些行（筛选，可省略）
ORDER BY 列 [ASC|DESC]      -- 怎么排序（可省略）
LIMIT 数量;                 -- 最多取几行（可省略）
```

**SELECT 不修改任何数据**——放心大胆地试，这是最安全的学习方式。

## 7.2 最简查询

```sql
-- 查询所有学生（* 表示所有列）
SELECT * FROM school.students;

-- 只看姓名和城市（列名决定输出顺序）
SELECT name, city FROM school.students;
```

**`*` 只适合"人眼看"，写进程序/报表的查询要显式列名**：省流量、防表结构变化、语义清晰。教程演示用 `*`，是偷懒不是榜样。

```sql
-- 表达式和别名：算出来的列起个名字
SELECT student_no,
       name,
       CURRENT_DATE - birth_date AS 已出生天数,          -- 日期相减得天数（随当天变化）
       city AS 城市
FROM school.students;
```

`AS` 给列起别名（中文别名可以但建议英文小写+下划线）。`||` 是字符串拼接：

```sql
SELECT name || '（' || city || '）' AS 学生标签 FROM school.students;
```

## 7.3 WHERE：条件筛选

### 比较运算符

| 运算符 | 含义 | 例子 |
|---|---|---|
| `=` | 等于（**一个等号！**不是 ==） | `WHERE city = '北京'` |
| `<>` 或 `!=` | 不等于 | `WHERE gender <> 'M'` |
| `>` `<` `>=` `<=` | 大小比较 | `WHERE score >= 60` |
| `BETWEEN a AND b` | 区间（**闭区间**，含两端） | `WHERE score BETWEEN 80 AND 90` |
| `IN (值1, 值2, ...)` | 在列表中 | `WHERE city IN ('北京', '上海')` |
| `LIKE` / `ILIKE` | 模式匹配 / 不区分大小写 | `WHERE name LIKE '王%'` |
| `IS NULL` / `IS NOT NULL` | 空值判断（**不能用 = NULL**） | `WHERE score IS NULL` |

> `BETWEEN 80 AND 90` 是"80 ≤ x ≤ 90"。边界值经常出 bug，记住含两端。

### LIKE 通配符

- `%` 任意长度的任意字符；`_` 恰好一个字符。

```sql
WHERE name LIKE '王%'        -- 王开头（王小明、王芳……）
WHERE student_no LIKE 'S2023_01%'   -- 一个下划线匹配任意一个字符
WHERE city NOT LIKE '%京%'   -- 城市名不含"京"
```

### 逻辑运算符：AND / OR / NOT

```sql
SELECT name, city, gender FROM school.students
WHERE city = '北京' AND gender = 'F';        -- 北京的女同学

SELECT name FROM school.students
WHERE city = '北京' OR city = '上海';        -- 北京或上海
```

**优先级：NOT > AND > OR。**混用时无脑加括号，谁也不猜：

```sql
WHERE (city = '北京' OR city = '上海') AND gender = 'F'    -- 意图清晰
-- 不加括号时 PG 理解为：city='北京' OR (city='上海' AND gender='F')，语义完全不同！
```

### 成绩单上的 NULL（预告）

`score` 为 NULL 表示"还在读、未考试"：

```sql
SELECT * FROM school.enrollments WHERE score = NULL;      -- ✗ 永远查不到任何行！
SELECT * FROM school.enrollments WHERE score IS NULL;     -- ✓ 正确姿势
```

`NULL` 表示"未知"，和任何值比较的结果还是"未知"（不是 true）。[第 10 章](第10章_NULL与常用函数.md)系统讲三值逻辑，此处先背结论。

## 7.4 ORDER BY：排序

```sql
SELECT name, birth_date FROM school.students
ORDER BY birth_date;                     -- 默认 ASC 升序（从小到大）

SELECT name, score FROM school.enrollments
ORDER BY score DESC                      -- DESC 降序；NULL 默认排在最后
LIMIT 5;                                 -- 只看前 5 行
```

- 多列排序：`ORDER BY city ASC, birth_date DESC`——先按城市升序，同城市的再按生日降序；
- **NULL 的位置可以控制**：`ORDER BY score DESC NULLS FIRST`（空值排最前，[第 10 章](第10章_NULL与常用函数.md)会用到）；
- `LIMIT n OFFSET m`：跳过前 m 行再取 n 行——分页的基础（`LIMIT 10 OFFSET 20` = 第 3 页每页 10 条）。

> **没有 ORDER BY，就没有"顺序"**。SQL 不保证无 ORDER BY 时的返回顺序，任何依赖"默认顺序"的程序都是 bug 温床。

## 7.5 DISTINCT：去重

```sql
SELECT DISTINCT city FROM school.students;          -- 学生来自哪些城市（重复的只留一个）
SELECT DISTINCT city, gender FROM school.students;  -- 城市组合去重：北京-男 和 北京-女 算两行
```

DISTINCT 作用于**整个选出的列组合**，不是单列。

## 7.6 综合示例

"2023 级入学的北京或上海学生，按入学日期倒序、同日期再按姓名排，只看前 5 名的学号和姓名"：

```sql
SELECT student_no, name, city, enrolled_on
FROM school.students
WHERE enrolled_on >= DATE '2023-09-01'
  AND city IN ('北京', '上海')
ORDER BY enrolled_on DESC, name
LIMIT 5;
```

对照骨架逐段读：`SELECT` 投影 → `FROM` 来源 → `WHERE` 筛行 → `ORDER BY` 排序 → `LIMIT` 截断。**写 SQL 的思维顺序也是这个**，先想"要哪些行"再想"取哪些列"。

## 7.7 书写风格：三个好习惯

1. **关键字大写、列名表名小写**（PG 不区分大小写，但统一风格大大提升可读性）；
2. **一个子句一行**，长条件换行缩进——半年后的自己会感谢你；
3. **先 WHERE 后 ORDER BY 的顺序不能乱**：标准子句顺序固定为
   `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`（中间两个下一章登场）。

## 本章小结

- SELECT 骨架五段：投影/来源/筛行/排序/截断；
- WHERE 是行过滤器：`= <>`、`BETWEEN`（闭区间）、`IN`、`LIKE`（`%` 和 `_`）、`IS NULL`；AND/OR 混用必加括号；
- 排序 `ORDER BY ... ASC|DESC`，多级排序逗号分隔；分页 `LIMIT n OFFSET m`；
- `DISTINCT` 对整行组合去重；
- 两个永远：`NULL` 永远用 `IS NULL` 判断；结果顺序永远靠 ORDER BY 保证。
