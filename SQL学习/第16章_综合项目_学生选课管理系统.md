## 16.1 需求（像甲方一样写清楚）

为某学院开发选课管理系统，功能：

1. 维护**院系、教师、学生、课程**基础信息；
2. 学生**选课/退课**；
3. 教师**录成绩**；
4. 查询服务：课表、成绩单、挂科预警、开课统计；
5. 权限：教务管理员可读写，教师只能读全部+改成绩，学生只能读自己的信息；
6. 数据安全：每天自动备份，可恢复。

## 16.2 设计：ER 图与表结构

先画实体关系（ER）——四实体 + 一关系表：

```text
departments 1 ──── n teachers          （一个院系多名教师）
teachers     1 ──── n courses          （一名教师开多门课）
students     n ──── n courses          （多对多，通过 enrollments 落地）
```

设计决策（每一条都对应[第 5 章](第05章_建表_数据类型与约束.md)某个知识点）：

| 决策 | 知识点 |
|---|---|
| 选课关系单独建表，`(student_id, course_id)` 唯一 | 多对多 + 复合唯一约束 |
| score 可空（未考试=在读） | NULL 语义 |
| 删学生 → 选课记录级联删除 | ON DELETE CASCADE |
| 删教师 → 课程保留、教师置空 | ON DELETE SET NULL |
| 成绩 0~100、学分 0.5~10 | CHECK 约束 |
| 金额/成绩用 numeric | 精确小数 |
| 事件时间用 timestamptz | 时区安全 |

## 16.3 分层实现查询接口（项目核心交付物）

真实系统不直接暴露表，而是提供**视图**和**函数**作为接口——既安全又复用。

### ① 视图 VIEW：把复杂查询固化成"虚拟表"

```sql
-- 视图1：课程详情（课程 + 教师 + 院系 一屏展示）
CREATE OR REPLACE VIEW school2.v_course_detail AS
SELECT c.course_id,
       c.course_name,
       c.credit,
       t.name       AS teacher_name,
       d.dept_name,
       COUNT(e.enrollment_id)                          AS enrolled_cnt,
       ROUND(AVG(e.score), 1)                          AS avg_score
FROM school2.courses c
LEFT JOIN school2.teachers     t ON t.teacher_id = c.teacher_id
LEFT JOIN school2.departments  d ON d.dept_id   = t.dept_id
LEFT JOIN school2.enrollments  e ON e.course_id  = c.course_id
GROUP BY c.course_id, c.course_name, c.credit, t.name, d.dept_name;
```

```sql
-- 视图2：学生成绩单与挂科预警（第 9-11 章的综合应用）
CREATE OR REPLACE VIEW school2.v_transcript AS
SELECT s.student_no,
       s.name,
       COUNT(e.score)                              AS graded_cnt,
       ROUND(AVG(e.score), 1)                      AS avg_score,
       COUNT(*) FILTER (WHERE e.score < 60)        AS fail_cnt,
       CASE WHEN COUNT(e.score) = 0 THEN '无成绩'
            WHEN COUNT(*) FILTER (WHERE e.score < 60) = 0 THEN '正常'
            WHEN COUNT(*) FILTER (WHERE e.score < 60) <= 2 THEN '预警'
            ELSE '严重预警' END                     AS status
FROM school2.students s
LEFT JOIN school2.enrollments e ON e.student_id = s.student_id
GROUP BY s.student_no, s.name;
```

使用视图就像用表：

```sql
SELECT * FROM school2.v_course_detail WHERE enrolled_cnt >= 3;
SELECT * FROM school2.v_transcript WHERE status <> '正常'
ORDER BY fail_cnt DESC;      -- 预警名单：5 名挂 1 门的学生 + 曹阳（无成绩）
```

> 视图是**存查询不存数据**——每次查询实时计算。想让视图可 UPDATE 并落到基表，用简单视图即可（PG 支持自动更新视图）；复杂场景学 INSTEAD OF 触发器（进阶，暂不展开）。

### ② 函数：把业务逻辑封装成"按钮"

```sql
-- 函数：给某学生某课程登记成绩（带合法性校验），成功返回说明
CREATE OR REPLACE FUNCTION school2.fn_set_score(
    p_student_no varchar,
    p_course_name varchar,
    p_score numeric)
RETURNS text
LANGUAGE plpgsql
AS $$
DECLARE
    v_sid int; v_cid int;
BEGIN
    SELECT student_id INTO v_sid FROM school2.students WHERE student_no = p_student_no;
    SELECT course_id  INTO v_cid FROM school2.courses WHERE course_name = p_course_name;
    IF v_sid IS NULL OR v_cid IS NULL THEN
        RETURN '错误：学生或课程不存在';
    END IF;
    IF NOT EXISTS (SELECT 1 FROM school2.enrollments
                   WHERE student_id = v_sid AND course_id = v_cid) THEN
        RETURN '错误：该学生未选此课程';
    END IF;
    UPDATE school2.enrollments
    SET score = p_score
    WHERE student_id = v_sid AND course_id = v_cid;
    RETURN '已登记：' || p_student_no || ' 的 ' || p_course_name || ' = ' || p_score;
END;
$$;

-- 调用（函数调用要包在 SELECT 里）：
SELECT school2.fn_set_score('S2023003', '数据库原理', 91.5);
```

这段 PL/pgSQL 是教程里第一段"程序化" SQL：变量（DECLARE）、分支（IF）、错误处理（提前 RETURN）。**会写函数，SQL 就从"查询语言"升级成"开发语言"**。

### ③ 事务性业务：选课 = 一次原子操作

```sql
-- 存储过程式用法：选课必须满足"未选过 + 空位检查"两个条件才算成功
BEGIN;
INSERT INTO school2.enrollments (student_id, course_id)
SELECT student_id, course_id
FROM school2.students, school2.courses
WHERE student_no = 'S2023005' AND course_name = '微观经济学'
ON CONFLICT (student_id, course_id) DO NOTHING;    -- 重复选课：静默跳过
COMMIT;
```

## 16.4 权限落地（第 15 章方案直接套用）

| 账号 | 权限 |
|---|---|
| `jw_admin`（教务） | school2 模式全部读写 |
| `teacher_grp`（组） | 全部表 SELECT + `fn_set_score` 执行权限（改成绩只能走函数，防绕过校验） |
| `student_reader`（演示） | 仅 `v_transcript` 视图的 SELECT |

```sql
-- 教师组：能读、能通过函数改分，但不能直接 UPDATE 表
CREATE ROLE teacher_grp NOLOGIN;
GRANT USAGE ON SCHEMA school2 TO teacher_grp;
GRANT SELECT ON ALL TABLES IN SCHEMA school2 TO teacher_grp;
GRANT EXECUTE ON FUNCTION school2.fn_set_score(varchar, varchar, numeric) TO teacher_grp;
-- 注意：teacher_grp 没有 enrollments 的 UPDATE 权限——想改成绩只能走带校验的函数

CREATE ROLE teacher_li LOGIN PASSWORD '...';
GRANT teacher_grp TO teacher_li;
```

**这个设计的妙处**：权限 + 函数校验双层防线，`teacher_li` 即便拿到 psql 也无法把成绩改成 999（CHECK 约束）、也无法给没选课的学生录分（函数校验）。
