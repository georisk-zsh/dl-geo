这一章不敲任何命令，只建立概念地图。概念清楚了，后面每一章都知道自己在学什么、处于哪个位置。

## 1.1 什么是数据

**数据（Data）是对客观事物的记录**：文字、数字、日期、图片、真假判断……都算。

生活例子——你填过的一张报名表：

```text
姓名：王小明    性别：男    生日：2005-03-12    城市：北京
```

这一行就是"数据"。当学校要管理**几千名学生**的报名信息时，单张表格不够用了，就需要"数据库"。

## 1.2 什么是数据库

**数据库（Database）是长期存放在计算机内、有组织、可共享的数据集合。**

打个比方：

- 一张纸条（记一个电话号码）→ 普通文件；
- 一个带标签的文件夹（按类别放好各种表）→ 数据库。

关键在"有组织"：数据不是胡乱堆着，而是按预先设计好的**结构**（表、列、约束）存放，所以能被高效查询和严格控制。

## 1.3 什么是数据库管理系统（DBMS）

**数据库管理系统（DBMS, Database Management System）是专门管理数据库的软件。**

继续用图书馆类比：

- 图书馆里所有的书 = 数据库（数据本身）；
- 图书馆的管理制度 + 管理员 + 借阅系统 = DBMS（管理数据的软件）。

你平时说的"我在学 PostgreSQL"，学的其实是某个 DBMS 的用法。常见的 DBMS 有：PostgreSQL、MySQL、Oracle、SQL Server、SQLite——它们都属于**关系型数据库管理系统（RDBMS）**。

## 1.4 PostgreSQL 是什么

**PostgreSQL（简称 PG，粉丝昵称"大象数据库"——看它的Logo就是一头大象）是一个开源、免费、功能强大的关系型数据库管理系统**，诞生于 1986 年加州大学伯克利分校，至今已发展近 40 年，是全球排名前五的开源数据库，被 Apple、Instagram、阿里巴巴等大量公司使用。

它的三个标签：

1. **开源免费**：任何人可免费商用，没有授权费；
2. **功能齐全**：很多商业数据库才有的能力（事务、窗口函数、全文检索、JSON、地理信息）它都有；
3. **标准严格**：对 SQL 标准支持最完整的数据库之一，学会 PG 再学别的数据库非常轻松。

## 1.5 什么是关系型数据库

**关系型数据库（Relational Database）用"多张二维表 + 表之间的关联关系"来组织数据。**

"二维表"就是你在 Excel 里见到的那种：横竖交叉的网格。

**为什么强调"关系"？** 看一个反面教材——把所有信息塞进一张大表：

```text
学生表（什么都存）：
姓名   | 课程1 | 成绩1 | 课程2 | 成绩2 | 课程3 | 成绩3 | ...
王小明 | 数据库 | 92    | 数学   | 85    | (空)  | (空)  |
李华   | 数据库 | 88    | 英语   | 91    | 数学  | 79    |
```

问题马上出现：有人选 3 门课、有人选 8 门课，列数怎么定？"课程1"里存了课程名，课程的信息（学分、老师）又要重复存无数遍——这就是**数据冗余**。

关系型的做法是**拆成多张表，各自存各自的信息，用"编号"互相引用**：

- `students` 表只存学生信息（每人一个 `student_id`）；
- `courses` 表只存课程信息（每门课一个 `course_id`）；
- `enrollments`（选课表）存"谁选了哪门课、考了多少分"，通过两个 id 把前两张表**关联**起来。

这种"分表 + 编号引用"的思想叫**规范化（Normalization）**，是[第 5 章](第05章_建表_数据类型与约束.md)和[第 16 章](第16章_综合项目_学生选课管理系统.md)设计表结构的理论核心。

## 1.6 表、行、列、字段、记录

还是用学生表举例：

```text
students 表（选课系统里的学生表）
┌────────────┬────────┬──────┬────────────┬──────┐
│ student_no │ name   │gender│ birth_date │ city │   ← 列（表头）
├────────────┼────────┼──────┼────────────┼──────┤
│ S2023001   │ 王小明 │ M    │ 2005-03-12 │ 北京 │   ← 行
│ S2023002   │ 李华   │ F    │ 2004-07-25 │ 上海 │   ← 行
└────────────┴────────┴──────┴────────────┴──────┘
```

| 术语 | 是什么 | 位置 |
|---|---|---|
| **表（Table）** | 数据的整体容器，一张二维网格 | 整个上图 |
| **列（Column）** | 表头的每一项，规定一类信息，且有固定**数据类型**（文本/日期/数字） | 竖着看 |
| **字段（Field）** | 列的另一种叫法。"students 表有 5 个字段" = "有 5 列" | 同列 |
| **行（Row）** | 一条完整的信息，网格里横着的一整条 | 横着看 |
| **记录（Record）** | 行的另一种叫法。1 行 = 1 条记录 | 同行 |

> 记不住"字段/记录"没关系，心里都换成"列/行"即可，SQL 圈两种叫法混用。

**行与列的数学本质**：关系型理论中表叫"关系（Relation）"，行叫"元组"，平时不用这些词，但面试可能会问。

## 1.7 主键

**主键（Primary Key）是表中用来唯一标识每一行的一列（或几列），特点是：不重复、不为空、一旦确定尽量不变。**

为什么需要它？学校有两个叫"王小明"的学生怎么办？靠姓名无法区分。所以给每个学生发一个**学号**——学号就是 students 表天然的主键。

主键的三个硬规矩：

1. **唯一**：任意两行的主键值不能相同；
2. **非空**：主键列必须填写；
3. **稳定**：不要用会变的信息（比如手机号——学生会换号）。

```text
student_id（主键） | student_no | name  | ...
1                 | S2023001   | 王小明 |
2                 | S2023002   | 李华   |
↑ 数字编号，数据库可以自动生成（第 5 章的 IDENTITY）
```

## 1.8 外键

**外键（Foreign Key）是本表中指向另一张表主键的一列，表示"我这行数据属于你那行"。**

`enrollments`（选课表）：

```text
enrollment_id | student_id | course_id | score
101           | 1          | 1         | 92.0
102           | 1          | 3         | 85.0
103           | 2          | 1         | 88.0
                ↑ 指向 students 表的主键
                             ↑ 指向 courses 表的主键
```

第 101 行的意思："1 号学生选了 1 号课程，得了 92 分"。

外键的两大价值：

1. **防止脏数据**：数据库会拒绝插入 `student_id = 999`（不存在的学生）的选课记录——外键自动校验；
2. **表达关联**：查询"王小明选了哪些课"时，数据库顺着外键把三张表连起来（[第 9 章](第09章_多表连接JOIN.md) JOIN）。

## 1.9 什么是模式（Schema）

**模式（Schema）是数据库内部的"文件夹"，用来把表按用途分组。**

生活类比：数据库 = 你家的文件柜，模式 = 柜子里的抽屉——"票据"一个抽屉、"说明书"一个抽屉，不会混放。

为什么要分模式？

- 一个库里既有"教学"相关的表，又有"图书借阅"相关的表，分放在 `school`、`library` 两个模式里，互不干扰；
- 同名的表可以在不同模式里共存：`school.students` 和 `library.students` 互不冲突；
- 权限可以按模式整体授权（[第 15 章](第15章_用户权限与安全.md)）。

> **MySQL 用户的坑**：MySQL 里 `database` 和 `schema` 是同义词；PostgreSQL 里它们是**两层不同结构**（见 1.11）。

## 1.10 什么是数据库服务器

**数据库服务器（Database Server）就是一台安装并运行着 PostgreSQL 软件、专门对外提供数据存取服务的计算机**（通常是 Linux 服务器）。

它的工作模式是**客户端/服务器（C/S）架构**，一定要分清两个角色：

```text
┌──────────────────┐   网络（本机或远程）   ┌─────────────────────┐
│ 客户端 Client     │ ──────────────────→  │ 服务器 Server        │
│ - psql 命令行     │   ① 发送 SQL         │ - 运行 PostgreSQL   │
│ - pgAdmin 界面    │ ←──────────────────  │ - 存储并管理数据     │
│ - 你写的程序      │   ② 返回结果         │ - 默认监听 5432 端口 │
└──────────────────┘                      └─────────────────────┘
```

- 你在 psql 里敲的每条 SQL，都是**发给服务器**，由服务器执行后**把结果传回来**；
- 服务器和客户端可以在同一台电脑（本教程大部分场景），也可以服务器在机房、客户端在你笔记本上（[第 2 章](第02章_安装与服务管理.md)的远程连接配置）。

## 1.11 PostgreSQL 的层级关系：服务器 → 数据库 → 模式 → 表

PostgreSQL 一切对象自上而下分四层，这个结构必须刻在脑子里：

```text
PostgreSQL 服务器（一台装了 PG 的 Linux 机器，监听 5432 端口）
└── 数据库 beginner_pg（一个数据"文件柜"）
    └── 模式 school（柜子里的"抽屉"）
        ├── students 表      （学生信息）
        ├── teachers 表      （教师信息）
        ├── courses 表       （课程信息）
        ├── enrollments 表   （选课成绩）
        └── departments 表   （院系信息）
```

同一台服务器上可以有多个数据库；一个数据库里可以有多个模式；一个模式里有多张表。**访问一张表的完整写法是三层前缀**：

```sql
SELECT * FROM beginner_pg.school.students;
--                     └─库   └─模式 └─表（实际写 SQL 时通常会省略库，第 4 章讲原因）
```

三个默认自带对象（先记住名字，后面章节会用到）：

| 对象 | 说明 |
|---|---|
| `postgres` 数据库 | 安装时自带的默认库，一般不用来存业务数据 |
| `public` 模式 | 每个数据库自带的默认模式，不指定模式时表会建在这里 |
| `postgres` 用户 | 自带的超级管理员账号 |

## 1.12 PostgreSQL 与 MySQL 的简单区别

两者都是开源关系型数据库，选型对比：

| 对比项 | PostgreSQL | MySQL |
|---|---|---|
| 定位 | 功能全面、标准严格，"学院派" | 轻量易用、普及度高，"实用派" |
| SQL 标准 | 实现最完整之一（窗口函数、CTE、递归查询全都有） | 部分高级特性较晚才支持 |
| 数据类型 | 丰富：数组、JSON、UUID、地理信息（PostGIS）、自定义类型 | 以基础类型为主 |
| 严格性 | 默认严格（写错数据直接报错，挡住脏数据） | 历史上有宽松模式（错误数据可能被悄悄截断） |
| 复杂查询/分析 | 强项：优化器对复杂 JOIN、子查询处理更好 | 简单读多写少场景速度优秀 |
| 用户体系 | 角色是**整个集群（服务器）级**对象，所有数据库共享同一套定义；授权可按库/模式/表/列精细控制 | 账号定义在服务器级（`mysql.user`），但授权习惯按数据库（`db.*`）划分，粒度较粗 |
| schema 含义 | database 下的命名空间（两层结构） | 与 database 同义 |

> 类比：MySQL 像自动挡家用车，上手快；PostgreSQL 像一台操控精准的工程车，规矩多但天花板高。学会 PG，MySQL 一周就能上手；反过来则要补很多概念。

## 1.13 PostgreSQL 与 Excel 的区别（概念视角）

[第 0 章](第00章_学习准备.md)从"使用场景"比过一次，这里从"概念结构"再对齐一次，帮你把 Excel 经验**迁移**过来：

| Excel 概念 | PostgreSQL 概念 | 迁移注意 |
|---|---|---|
| 工作簿（.xlsx 文件） | 数据库 | 库的容量和安全性远超工作簿 |
| 工作表（Sheet1、Sheet2…） | 表 | 表之间可以真正建立外键关联，Sheet 之间不行 |
| 一行 | 记录 | PG 强制每行列数一致、类型一致；Excel 同列可混文本和数字 |
| 一列 | 字段 | PG 列有**类型**：`DATE` 列存不了"下个月"这种文字 |
| 表头 | 列名 | 列名必须合法且唯一 |
| 单元格格式校验 | 约束（主键/唯一/检查） | PG 在**写入时**强制校验，Excel 的数据验证可被粘贴绕过 |
| 冻结窗格/筛选 | 索引、视图 | 不是一个层面的东西，后面章节细讲 |

## 本章小结

- 数据（原料）→ 数据库（仓库）→ DBMS（仓库管理软件）；PostgreSQL 就是一款顶级开源 DBMS；
- 关系型 = **多张二维表 + 主键唯一标识 + 外键互相引用**，避免一张大表打天下；
- 行 = 记录，列 = 字段，主键 = 行的身份证，外键 = 指向别的表的指针；
- 四层结构：**服务器 → 数据库 → 模式 → 表**，本教程主线是 `服务器 → beginner_pg → school → 五张表`；
- 客户端（psql/pgAdmin）发 SQL，服务器执行并返回结果，默认端口 5432。
