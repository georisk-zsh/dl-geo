## 1. 这一篇解决什么问题

模型代码写得再漂亮，喂进去的数据错一格，结论全错。监测数据的"脏"有个特点：**它不报错**——程序照跑、loss 照降、指标还挺好看，只是模型学到的东西毫无意义。等你发现时，几周已经过去了。

更隐蔽的是**数据泄漏**：训练时不小心用了"预测时刻还不可知"的信息。它让离线指标虚高 10%~50%，上线立刻崩，而且**从指标曲线上完全看不出来**。本篇把这两类事故各拆成几个具体场景，逐个给检测与修复方法。

```mermaid
flowchart LR
    A["原始 CSV<br/>（脏的）"] --> B["① 审计<br/>只看不改"]
    B --> C["② 时间轴<br/>排序·去重·补日历"]
    C --> D["③ 缺失<br/>插值 or 保留"]
    D --> E["④ 异常<br/>野值·台阶·漂移"]
    E --> F["⑤ 防泄漏划分<br/>70/15/15 按时间"]
    F --> G["⑥ 标准化<br/>只在训练段 fit"]
    G --> H["⑦ 滑窗张量化<br/>(N, T, F)"]
```

**本篇的练习数据**是一份合成的两年期（2023-01-01 ~ 2024-12-31，日频）监测数据，字段如下：

| 列 | 含义 | 单位 |
|---|---|---|
| `date` | 日期 | — |
| `rainfall_mm` | 当日降雨量 | mm |
| `reservoir_m` | 库水位 | m |
| `temp_c` | 气温 | ℃ |
| `disp_rate_mm_d` | **位移速率（预测目标）** | mm/d |

生成方式在 [make_dirty_data.py](make_dirty_data.py)：先按物理规律合成"干净数据"（降雨 → 15 天指数滞后核 → 有效降雨驱动位移；低水位小幅贡献），再**故意植入 8 处典型污染**。污染清单在[附录 A](#附录-a污染清单先自己找再对答案)，**建议先按正文流程自己找一遍再看答案**——这 8 处覆盖了真实项目里 90% 的脏数据形态。

## 2. 第 0 步：审计——永远先看懂，再动手

拿到数据的**第一件事不是清洗，是审计**。审计阶段**只打印、不修改**——过早动手"修"，往往把没看懂的信号修没了。

```python
import numpy as np

print('负速率:', (raw['disp_rate_mm_d'] < 0).sum())
```

**这一眼要看出来五件事**：

| 发现 | 说明 | 对应污染 |
|---|---|---|
| 734 行但两年只有 731 天 | 有重复行 | ⑦ 重复日期 |
| **没按时间排序** | 有乱序行 | ⑧ 时间乱序 |
| `rainfall_mm` 缺 12 个 | 雨量计偶发丢数 | ② 随机缺失 |
| `disp_rate_mm_d` 连续缺 7 个 | 传感器整段故障 | ① 连续缺失 |
| **负降雨 1 条** | 物理不可能 | ⑥ 符号错误 |

> 📌 **审计自检清单**（任何新数据先过一遍）：行数 vs 期望频次 × 时间跨度；时间列 dtype 与排序；重复时间戳；各列缺失数与**缺失的位置分布**（随机散点还是连续段？）；取值范围的物理合法性（负降雨？水位超量程？）；单位量级（雨量是 mm 还是 m？）。

缺失的位置分布比缺失数量更重要：

```python
gap = raw.set_index('date')['disp_rate_mm_d'].isna()

print('速率缺失段数:', runs.nunique(), ' 最长连续:', runs.value_counts().max())
print('雨量缺失日期:', raw.loc[raw['rainfall_mm'].isna(), 'date'].dt.date.tolist()[:5], '…')
```

```text

```

速率是**一段连续 7 天**（传感器故障），雨量是**散点**（通信丢包）——两种模式的修复策略完全不同，第 4 节再处理。

## 3. 时间轴修复：排序 · 去重 · 补齐日历

时间序列的主键是时间轴。**先修轴，再修值**——顺序反了，一切统计都不可信。

```python
full = pd.date_range(raw['date'].min(), raw['date'].max(), freq='D')
print('期望天数:', len(full))

df = (raw.sort_values('date')                    # 排序
        .drop_duplicates('date', keep='last')     # 去重：同一时刻重传时保留后到的
        .set_index('date')
        .reindex(full))                           # 补齐完整日历：缺日显式变成 NaN
df.index.name = 'date'
print('修复后:', df.shape, ' 剩余 NaN:', int(df.isna().sum().sum()))
```

```text
期望天数: 731
修复后: (731, 4)  剩余 NaN: 19
```

三步各管一种病：

1. **排序**：乱序行不修，后面所有按位置的滑窗都会错位；
2. **去重**（`keep='last'`）：同一时刻出现两行通常是"设备补传"，后到的那份是修正版。⚠️ 如果你的数据源是"前一行是修正版"，改 `keep='first'`——**这个选择属于业务知识，数据自己不会告诉你**；
3. **`reindex` 完整日历**：让"2 月 30 日不存在"（缺日）和"2 月 30 日仪器没数"（缺值）都统一显式成 `NaN`。734 行 → 731 行整，此后**任何 NaN 都是缺值**。剩余 19 个 NaN = 12 个雨量散点 + 7 个速率连续段，与 §2 审计完全对上——先修轴再修值，账才对得平。

## 4. 缺失值：短缺口插值，长缺口保留

修复策略按**缺口长度**和**变量类型**分：

| 情形 | 策略 | 理由 |
|---|---|---|
| 雨量散点缺失（12 天） | 填 0 | 连续观测都存在、只缺零星日，多半是"没下雨所以没发报"；填 0 对模型无害 |
| 速率 ≤6 天短缺口 | 线性插值 | 传感器小故障，前后观测足以约束中间值 |
| 速率 >6 天长缺口 | **保留 NaN + 加缺失指示列** | 缺口内插出来的都是"编的数"，模型有权知道这段是假的 |

**⚠️ 插值的边界条件（泄漏高发区）**：缺口**末端**的插值会用到缺口之后的观测——在"事后分析"里可以接受，在"预测流水线"里等于**用未来填过去**。本篇的流水线里，插值只用于**特征列的短缺口**；作为**预测目标**的速率长缺口，正确做法是让这些时刻的样本**退出训练**（第 7 节滑窗时自动跳过含 NaN 的窗），而不是把假数当标签。

```python
fix = df.copy()

# 零星雨量缺失填 0
fix['rainfall_mm'] = fix['rainfall_mm'].fillna(0.0)
# 速率短缺口插值（limit=6：最多补连续 6 天）
fix['disp_rate_mm_d'] = fix['disp_rate_mm_d'].interpolate(method='linear', limit=6, limit_direction='both')
print('修复后各列 NaN:')
print(fix.isna().sum())
```

```text
修复后各列 NaN:
rainfall_mm       0
reservoir_m       0
temp_c            0
disp_rate_mm_d    0
dtype: int64
```

（本例的 7 天缺口正好卡在 limit=6 的边上被插值补掉了——**真实项目里 7 天建议设 limit=3**，把长缺口留给指示列。这里保留插值结果是为了后面演示流程完整；判定原则记牢即可。）

## 5. 异常值：三种坏法，三副药

"异常"没有统一定义——**先问它违反了什么**，再决定怎么修。

### 5.1 物理不可能值（如负降雨）→ 只能置 0 或置 NaN

```python
print(fix.loc[fix['rainfall_mm'] < 0, 'rainfall_mm'])
fix.loc[fix['rainfall_mm'] < 0, 'rainfall_mm'] = 0.0   # 降雨不可能为负
```

```text
date
2023-05-31   -3.2
Freq: D, Name: rainfall_mm, dtype: float64
```

物理规则是**最强的检测器**，永远先查：降雨 $\ge 0$、水位在库容曲线范围内、位移速率不为负（本例设定蠕变方向为正）……这类规则一行代码，零误报。

### 5.2 孤立野值（单点尖峰）→ 稳健 z 分数（MAD）

雨量偶尔会混进"雷击脉冲"式野值。普通 z 分数（减均值除标准差）会被野值**本身抬高均值方差**，检测力下降；工程上用**中位数绝对偏差（MAD）**：

$$z_{\text{MAD}}=0.6745\times\frac{x-\text{median}(x)}{\text{MAD}(x)},\qquad \text{MAD}(x)=\text{median}\big(|x-\text{median}(x)|\big)$$

（0.6745 是"与标准差同尺度"的校准系数：正态数据下 $\text{MAD}\approx\sigma/0.6745$。）

**手算一个**——速率列的可疑点 2024-02-05，$x=7.375$，全列 $\text{median}=0.511$、$\text{MAD}=0.303$：

$$z_{\text{MAD}}=0.6745\times\frac{7.375-0.511}{0.303}=0.6745\times\frac{6.864}{0.303}=0.6745\times22.65\approx15.3$$

$|z|>6$（保守阈值）——**15 个 MAD 尺度以外**，孤立野值实锤。

```python
med = fix['disp_rate_mm_d'].median()
mad = (fix['disp_rate_mm_d'] - med).abs().median()
z = 0.6745 * (fix['disp_rate_mm_d'] - med) / mad
print('med=%.3f mad=%.3f' % (med, mad))
print('野值点:', z[z.abs() > 6].index.tolist(), ' z=%.1f' % z.max())

sp = z[z.abs() > 6].index[0]
fix.loc[sp, 'disp_rate_mm_d'] = np.nan                 # 置 NaN
fix['disp_rate_mm_d'] = fix['disp_rate_mm_d'].interpolate(   # 按短缺口插值回填
    method='linear', limit=6, limit_direction='both')
print('回填值: %.3f' % fix.loc[sp, 'disp_rate_mm_d'])
```

```text
med=0.511 mad=0.303
野值点: [Timestamp('2024-02-05 00:00:00')]  z=15.3
回填值: 0.081
```

（手算 15.3、程序 15.3，一致。）

处理：置 NaN 后按第 4 节短缺口插值，回填值 0.081，与前后观测衔接（$x=7.375$ 这种孤立尖峰没有任何物理过程能产生）。

### 5.3 台阶与漂移：系统性偏差，检测靠"对照"，修复要"留痕"

单点统计对**系统性偏差**无能为力——台阶前后各几百个点都"正常"。检测靠**差分/对照**：

**台阶（换仪器、改基准）**——查一阶差分：

```python
dz = fix['reservoir_m'].diff().abs()
print('|Δh| 分位数 p50/p90/p99: %.2f %.2f %.2f' % (dz.quantile(.5), dz.quantile(.9), dz.quantile(.99)))
print('最大日差: %.2f 于 %s' % (dz.max(), dz.idxmax().date()))
```

```text
|Δh| 分位数 p50/p90/p99: 0.14 0.21 0.24
最大日差: 2.43 于 2024-05-15
```

日变幅 99% 都在 0.24 m 以内，最大日差 **2.43 m**——超一个数量级，台阶实锤。校正量怎么估？

```python
before = fix.loc['2024-05-07':'2024-05-14', 'reservoir_m'].median()   # 跳跃日前 8 天
after  = fix.loc['2024-05-15':'2024-05-22', 'reservoir_m'].median()   # 后 8 天
print('局部中位数校正量: %.2f' % (after - before))
glob = fix.loc['2024-05-15':, 'reservoir_m'].median() - fix.loc[:'2024-05-14', 'reservoir_m'].median()
print('（错误示范）全局中位数校正量: %.2f' % glob)
```

```text
局部中位数校正量: 2.11
（错误示范）全局中位数校正量: 5.50
```

**为什么全局中位数差（5.50）不能用**：水位有年周期（±12 m），"跳跃日前全部"和"跳跃日后全部"落在季节曲线的不同位置上，5.50 里大半是**季节差**，拿它校正会把年周期一起抹掉。局部中位数（±8 天窗口内季节变化可忽略）给出 2.11——本例真值是 2.5（见附录），残余的 0.4 来自窗口内的缓慢水位趋势。**工程上若仪器比对记录（人工测量 vs 自动化）给出校正值，永远优先用记录值**；没有记录时局部法可用但要在报告里注明不确定性。

```python
fix.loc['2024-05-15':, 'reservoir_m'] -= (after - before)      # 台阶校正
dz2 = fix['reservoir_m'].diff().abs()
print('校正后最大日差: %.2f' % dz2.max())
```

```text
校正后最大日差: 0.32
```

从 2.43 回到 0.32（残余台阶 ~0.4 大部分藏在正常日变幅里），修复到位。**校正必须留痕**：改了哪些天、校正量多少、依据什么——写进数据日志（report 的 §1 就靠它）。

**单位漂移（量纲悄悄变了）**——单点统计、差分**全都正常**，检测只能靠**同比对照**：

```python
rain = fix['rainfall_mm']
w24 = rain.loc['2024-08-23':'2024-10-01'].sum()
w23 = rain.loc['2023-08-23':'2023-10-01'].sum()
print('同期 40 天雨量: 2023 年 %.1f mm  2024 年 %.1f mm  比值 %.2f' % (w23, w24, w24 / w23))
mon = rain.groupby(rain.index.to_period('M')).sum()
for m in ['05', '06', '07', '08']:
    print('  %s 月同比: %.2f' % (m, mon['2024-' + m] / mon['2023-' + m]))

fix.loc['2024-08-23':'2024-10-01', 'rainfall_mm'] *= 10   # 量级回乘
w24b = fix['rainfall_mm'].loc['2024-08-23':'2024-10-01'].sum()
print('修复后同期雨量: %.1f mm  比值 %.2f' % (w24b, w24b / w23))
```

```text
同期 40 天雨量: 2023 年 134.5 mm  2024 年 4.7 mm  比值 0.04
  05 月同比: 0.45
  06 月同比: 0.87
  07 月同比: 0.65
  08 月同比: 0.64
修复后同期雨量: 47.2 mm  比值 0.35
```

相邻月份同比都在 0.45~0.87 波动（年际丰枯），唯独 2024-08-23 之后 40 天掉到 **0.04**——**差了一个数量级**，且恰从某天起整段如此，这不是干旱，是**记录单位漂移**（某天起数据以 cm 记录但按 mm 汇入）。修复：该段 ×10，并在数据日志记录"依据同比断崖式差异定位、按数量级关系推定单位错误"。

> 🛑 **修复到这就该停**。修复后同期比值回到 0.35 左右，与相邻月同比同一量级——**不要**继续把它"校"到 1.00。年际降水本来就有丰枯，把 0.35 校到 1.00 就是在**制造假数据**。修到"物理上讲得通"，剩下的差异是真实世界的。

三种坏法对照总结：

| 病 | 检测器 | 修复 | 留痕 |
|---|---|---|---|
| 物理不可能（负降雨） | 物理规则 | 置 0 / NaN | 一行日志 |
| 孤立野值（尖峰） | 稳健 z（MAD），\|z\|>6 | 置 NaN 后短缺口插值 | 记录位置与 z 值 |
| 系统偏差（台阶/漂移） | 一阶差分 / 同比对照 | 局部中位数校正 / 量级回乘 | **必须**记校正量与依据 |

## 6. 防泄漏流水线：划分与标准化

清洗完成，进入**最容易犯法的地段**。泄漏（leakage）= 训练时用了预测时刻**还不可知**的信息。两条铁律：

**铁律 1：按时间顺序划分，绝不能随机打乱。** 明天的数据今天拿不到——随机划分等于让模型"提前看到未来"。

**铁律 2：一切统计量只在训练段计算。** 标准化的均值方差、特征筛选的相关性、调参的验证反馈——全部限定在"当时可知"的范围内。

```python
n = len(fix)
n_tr = int(n * 0.7)
n_va = int(n * 0.15)
print('划分: 训练 %d (%s → %s)  验证 %d  测试 %d'
      % (n_tr, fix.index[0].date(), fix.index[n_tr-1].date(), n_va, n - n_tr - n_va))
```

```text
划分: 训练 511 (2023-01-01 → 2024-05-25)  验证 109  测试 111
```

标准化——**只用训练段的均值方差**，同一套参数再变换验证/测试段：

```python
FEATS = ['rainfall_mm', 'reservoir_m', 'temp_c', 'disp_rate_mm_d']
mu = fix.iloc[:n_tr][FEATS].mean()     # ← 只在训练段算
sd = fix.iloc[:n_tr][FEATS].std()
Z = (fix - mu) / sd                    # 同一套 mu/sd 变换全部
print('训练段雨量均值 = %.3f' % mu['rainfall_mm'])
print('（错误示范）全段雨量均值 = %.3f' % fix['rainfall_mm'].mean())
```

```text
训练段雨量均值 = 1.779
（错误示范）全段雨量均值 = 1.717
```

差 0.06 mm——看着不大？**那是因为测试段信息本来就少**。这 0.06 里已经包含了未来两年的降水丰枯信息，标准化把模型的"零点"偷偷往测试分布上挪了；换到波动更大的变量（水位、位移）或更小的训练占比，偏移足以改变模型排序。**这不是"误差多大"的问题，是"信息从哪来"的问题**——测试信息以任何形式参与训练，指标就不再可信。

## 7. 滑窗张量化：从表格到 $(N, T, F)$

时序模型吃的是三维张量：$N$ 个样本、每个 $T$ 天历史窗口、每天 $F$ 个特征。滑窗规则（**因果性就体现在这里**）：

- 窗口 $[\,t-T,\ t-1\,]$ 的 $T$ 天做输入，第 $t$ 天的目标做标签——**窗口不含 $t$**，否则输入里就有答案；
- 目标是"明天的速率"时，标签换成 $t+1$，窗口仍到 $t-1$（若允许用"今天"做输入，则窗口到 $t$）；
- **窗口内含 NaN 的样本直接丢弃**——这就是第 4 节说的"长缺口退出训练"，无需手工挑。

```python
SEQ = 30
def make_windows(Z, start, end):
    arr = Z.values
    ti = Z.columns.get_loc('disp_rate_mm_d')
    X, y = [], []
    for t in range(max(start, SEQ), end):
        w = arr[t - SEQ:t]                # 输入：t-30 … t-1 共 30 天
        if np.isnan(w).any():
            continue                      # 含缺失的窗丢弃
        X.append(w)
        y.append(arr[t, ti])              # 标签：第 t 天速率
    return np.array(X), np.array(y)

X_tr, y_tr = make_windows(Z, SEQ, n_tr)
X_va, y_va = make_windows(Z, n_tr, n_tr + n_va)
X_te, y_te = make_windows(Z, n_tr + n_va, n)
print('X_tr', X_tr.shape, ' X_va', X_va.shape, ' X_te', X_te.shape)
```

```text
X_tr (481, 30, 4)  X_va (109, 30, 4)  X_te (111, 30, 4)
```

$(481, 30, 4)$：481 个样本、每个 30 天窗口、4 个特征——这就是案例 1/3 的 LSTM、CNN-Transformer 直接吃的形状（案例 2 GCN 只需把 $N$ 换成"节点×样本"，案例 4 XGBoost 把窗口拍平成 $30\times4=120$ 列）。验证/测试段**不丢弃含 NaN 的窗**（本例无，但原则不同：评估必须覆盖全时段；真有缺口时报告里注明"该时段未评估"）。

> ⚠️ 验证段第一个窗口会**跨过训练/验证边界**取到训练段末尾的天数——这不是泄漏：窗口取的是**标签日之前**的信息，而标签仍在验证段内。泄漏的判定标准永远是"**信息相对标签的时刻**"，不是"文件位于哪一段"。

## 9. 自检问题

**1. 为什么不能先随机打乱再 70/15/15 划分？**

> 因为时序样本不独立同分布：相邻天高度相关。随机划分后，训练集里几乎总有"测试日的前一天"，模型实质上在做"已知昨天预测今天"的插值任务——离线指标虚高，真实预测（未来是真未知）必然掉下来。

**2. 全段标准化（用全部 731 天的均值方差）具体错在哪一步？**

> 错在 mu/sd 的计算范围。全段统计量是"训练 + 验证 + 测试"的函数，测试段的分布信息由此进入每个训练样本的取值——测试信息以常数（mu/sd）的形式参与了训练。判定标准：**任何写进模型或样本变换的数字，都必须能追溯到训练段**。

**3. 速率缺 7 天，为什么"插值补上再训练"是次优解？**

> 插出来的 7 个标签是前后观测的线性内插，不是真实位移。模型会把"雨量变化时速率却线性平滑"这段假数据当规律学进去。更稳妥：短缺口（≤3 天）插值，长缺口保留 NaN、样本退出训练（滑窗自动丢弃），并加缺失指示特征。

**4. 台阶校正为什么用"跳跃日前后各 8 天的中位数差"，不用前后各 400 天？**

> 全局窗口跨越季节周期，中位数之差混入季节差（本例 5.50 vs 局部 2.11，真值 2.5）；局部窗口内季节变化可忽略。但局部窗口也含缓慢趋势，所以校正量仍有 ~0.4 不确定性——有仪器比对记录时以记录为准。

**5. 第 7 节验证段窗口跨过训练/验证边界，为什么不算泄漏？**

> 泄漏看信息与**标签时刻**的相对位置：窗口数据全部早于标签日，标签在验证段——信息流只从过去流向未来。若把标签日的数据放进窗口（或用验证段统计量做标准化），才是泄漏。
